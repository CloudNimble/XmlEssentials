## Summary

Provides metadata about a set of types that is relevant to XML serialization, and provides a base for source-generated contexts.

## Usage

You don't use `XmlSerializerContext` directly. You declare a partial class that derives from it, list your types with `[XmlSerializable]`, and the source generator in the `XmlEssentials` package writes the rest of the class.

```csharp
[XmlSerializable<Order>]
public partial class OrderXmlContext : XmlSerializerContext
{
}
```

The generated half adds a static `Default` instance, a parameterless constructor, a constructor that takes `XmlSerializerOptions`, one `XmlTypeInfo<T>` property for each type, and an implementation of `GetTypeInfo`. Pass a type info property, or the context itself, to an `XmlSerializer` overload:

```csharp
string xml = XmlSerializer.Serialize(order, OrderXmlContext.Default.Order);

Order? copy = XmlSerializer.Deserialize(xml, OrderXmlContext.Default.Order);
```

A context is bound to one `XmlSerializerOptions` instance, available from `Options`. The constructor makes the context the `TypeInfoResolver` of those options.

The class is the counterpart of `JsonSerializerContext` in System.Text.Json. For the full procedure, see [How to use source generation](/guides/source-generation).

## Remarks

This class is analogous to `JsonSerializerContext` in `System.Text.Json`.

## Examples

### Serialize and deserialize with generated type info

```csharp
Order order = CreateOrder();

string xml = XmlSerializer.Serialize(order, OrderXmlContext.Default.Order);
output.WriteLine(xml);

Order? copy = XmlSerializer.Deserialize(xml, OrderXmlContext.Default.Order);
output.WriteLine($"Order {copy!.Id} for {copy.Customer}: {copy.Lines.Count} lines");
```

The code produces the following output:

```text
<?xml version="1.0" encoding="utf-8"?><Order Id="1042"><Customer>Ada</Customer><Line><Quantity>1</Quantity><Sku>KB-01</Sku></Line><Line><Quantity>2</Quantity><Sku>MS-02</Sku></Line></Order>
Order 1042 for Ada: 2 lines
```

### Create a context from your own options

```csharp
var options = new XmlSerializerOptions
{
    NewLine = "\n",
    OmitXmlDeclaration = true,
    WriteIndented = true,
};
var context = new OrderXmlContext(options);

string xml = XmlSerializer.Serialize(CreateOrder(), context.Order);
output.WriteLine(xml);
```

The code produces the following output:

```xml
<Order Id="1042">
  <Customer>Ada</Customer>
  <Line>
    <Quantity>1</Quantity>
    <Sku>KB-01</Sku>
  </Line>
  <Line>
    <Quantity>2</Quantity>
    <Sku>MS-02</Sku>
  </Line>
</Order>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/32_UseSourceGeneration.cs)

## Best Practices

- **Use `Default` unless you need other options.** It's created once and shared. When you do pass options to the constructor, create that context once and keep it.
- **Prefer the `XmlTypeInfo<T>` properties to the context overloads.** `OrderXmlContext.Default.Order` fails to compile when the type isn't in the context. `XmlSerializer.Serialize(value, context)` finds out at run time.
- **List every root type.** A generated context uses no reflection: a type that it doesn't list and can't reach from a listed type is a `NotSupportedException`, unless it is a built-in value. That includes a collection or array type that you serialize as the document element, so list it too.
- **Set naming policies with `[XmlSourceGenerationOptions]`.** Generated converters fix member names at compile time, so a policy set only on run-time options changes the name of the document element and nothing else.
- **Give a type that needs a custom converter the `[XmlConverter]` attribute.** A generated context then uses the converter for that type. A converter in `XmlSerializerOptions.Converters` for a type the context generates code for throws `NotSupportedException`; put such a type in a metadata-mode context, or serialize it with reflection.
- **Serialize a type that declares `[XmlDerivedType]` with reflection.** The generator reports `XMLXE008` for it in every mode.

## Considerations

- **The constructor changes the options you pass.** It sets `TypeInfoResolver` on them, and throws `InvalidOperationException` when they're read-only. `XmlSerializerOptions.Default`, `Web`, and `Strict` are read-only. If you pass the same options to two contexts, the second one becomes the resolver.
- **Type info belongs to the context's options.** `OrderXmlContext.Default.Order.Options` is the options of `Default`, whichever options instance asked for it.
- **Contexts combine through `TypeInfoResolverChain`.** A generated `GetTypeInfo` returns `null` for a type the context neither lists nor reaches, unless the type is a built-in value, an XML value, or `object`, so the next context in the chain is asked. The options that hold the chain decide how each type is written: a generated context creates type info for the options that ask. A context you write by hand answers with whatever its `GetTypeInfo(Type)` returns.
- **A generated converter follows an option or refuses it.** It reads `DefaultIgnoreCondition`, `PropertyNameCaseInsensitive`, and `NumberHandling` from the options when it runs. The naming policies, `DefaultPropertyMapping`, and `IncludeFields` are compiled in from `[XmlSourceGenerationOptions]`; options that ask for anything else, or that set `IgnoreReadOnlyProperties`, `IgnoreReadOnlyFields`, or a converter for a type the generated code writes itself, make the context throw `NotSupportedException` when it creates the type info. A `ReferenceHandler` makes the converter throw `NotSupportedException`.
- **Interceptors route other calls to the context.** With the package's build file in effect, `XmlSerializer.Serialize<T>(value)` and `XmlSerializer.Deserialize<T>(input)` for a listed type are rewritten to use the context's `Default` instance. A call that passes an `XmlSerializerOptions` argument is never rewritten. See [Interceptors](/guides/reflection-vs-source-generation#interceptors).
- **Unlike `JsonSerializerContext`,** the class has no `GeneratedSerializerOptions` member. The generated code is a constructor and properties.
