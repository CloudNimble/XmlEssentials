## Summary

Metadata for serializing *T*.

## Usage

An `XmlTypeInfo` is the serializer's contract for one type: the converter that reads and writes it, the name of its document element, and the options it was built for. `XmlTypeInfo<T>` is the typed form you pass to `XmlSerializer`.

You don't create type info. You get it from one of two places:

- A property of a source-generated context, such as `OrderXmlContext.Default.Order`.
- An options instance, with `XmlSerializerOptions.GetTypeInfo<T>()`, `GetTypeInfo(Type)`, or `TryGetTypeInfo`.

Pass it to an `XmlSerializer` overload. These overloads use no reflection, so they're safe in trimmed and Native AOT applications:

```csharp
string xml = XmlSerializer.Serialize(order, OrderXmlContext.Default.Order);

Order? copy = XmlSerializer.Deserialize(xml, OrderXmlContext.Default.Order);
```

The classes correspond to `JsonTypeInfo` and `JsonTypeInfo<T>` in System.Text.Json.

## Type Parameters

- `T` - The CLR type.

## Examples

### Read the contract of a type

The following example lists the members of `Order` as the serializer maps them. The type info comes from a context in metadata mode, which builds it with the run-time resolver.

```csharp
XmlTypeInfo<Order> metadata = MetadataOrderXmlContext.Default.Order;

output.WriteLine($"Root element: {metadata.RootName.LocalName}");
foreach (XmlPropertyInfo property in metadata.Properties)
{
    string kind = property.IsAttribute ? "attribute" : "element";
    output.WriteLine($"{property.Name.LocalName}: {kind}, {property.PropertyType.Type.Name}");
}
```

```csharp
public sealed class Order
{
    public string? Customer { get; set; }

    [XmlAttribute]
    public int Id { get; set; }

    [XmlElement("Line")]
    public List<OrderLine> Lines { get; set; } = [];
}
```

The code produces the following output:

```text
Root element: Order
Id: attribute, Int32
Customer: element, String
Line: element, List`1
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/33_SourceGenerationModes.cs)

## Considerations

- **Type info is read-only.** Every property has a getter only. Unlike `JsonTypeInfo`, you can't add, remove, or change members to customize a contract. Change the mapping with attributes, options, or a custom converter.
- **You can't derive from it or construct it.** The constructors aren't accessible outside the library.
- **`Properties` is filled only by the run-time resolver.** Type info from the reflection resolver, or from a context in metadata mode, lists one `XmlPropertyInfo` for each member in the order they're written. Type info for a generated converter, a simple value, or a custom converter has an empty list.
- **`CreateObject` is `null` unless the type is an object with a parameterless constructor** that the run-time resolver bound. It's `null` for type info from a generated converter.
- **Type info is bound to its `Options`.** The serializer uses those options when you pass the type info, whatever other options exist. Type info from `XmlSerializerOptions.GetTypeInfo` is cached on that instance, and asking for it makes the instance read-only.
- **It's safe to share.** Keep and reuse type info across threads, as you would the options or the context it came from.
