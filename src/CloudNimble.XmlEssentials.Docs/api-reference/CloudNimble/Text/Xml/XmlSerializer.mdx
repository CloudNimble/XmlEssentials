## Summary

Serializes CLR values to UTF-8 XML and back. Analogous to `JsonSerializer`.

## Usage

`XmlSerializer` converts .NET objects to XML and back. It is a static class with the same shape as `JsonSerializer` in System.Text.Json: there is no instance to create or cache, and every method takes the value or the XML plus an optional [`XmlSerializerOptions`](/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions).

Call `Serialize` to get a `string`:

```csharp
var order = new PurchaseOrder
{
    Id = 1042,
    Customer = "Contoso",
    Placed = new DateOnly(2026, 3, 14),
    Total = 129.90m,
};

string xml = XmlSerializer.Serialize(order);
output.WriteLine(xml);
```

Call `Deserialize<TValue>` to turn XML into an object:

```csharp
PurchaseOrder? order = XmlSerializer.Deserialize<PurchaseOrder>(xml);
```

The methods come in families. Each family has overloads for reflection (`XmlSerializerOptions`), for a type known only at run time (`Type`), and for source generation (`XmlTypeInfo<TValue>` or `XmlSerializerContext`).

| To write to | Call | To read from | Call |
| --- | --- | --- | --- |
| A `string` | `Serialize` | A `string` or `ReadOnlySpan<char>` | `Deserialize` |
| A `byte[]` of UTF-8 | `SerializeToUtf8Bytes` | A `ReadOnlySpan<byte>` or `ReadOnlySequence<byte>` of UTF-8 | `Deserialize` |
| An `IBufferWriter<byte>` | `Serialize` | | |
| A `Stream` | `Serialize`, `SerializeAsync` | A `Stream` | `Deserialize`, `DeserializeAsync` |
| A `PipeWriter` | `SerializeAsync` | A `PipeReader` | `DeserializeAsync` |
| An open `Utf8XmlWriter` | `Serialize` | A `Utf8XmlReader` on a start tag | `Deserialize` |
| An `XmlDocument`, `XmlElement`, or `XmlNode` | `SerializeToDocument`, `SerializeToElement`, `SerializeToNode` | An `XmlDocument`, `XmlElement`, or `XmlNode` | `Deserialize` |
| A stream, one item at a time | `SerializeAsyncEnumerable` | A stream, one item at a time | `DeserializeAsyncEnumerable` |

For a walk through each destination and source, see [Serialize](/guides/serialize) and [Deserialize](/guides/deserialize).

## Remarks

Every overload resolves an [XmlTypeInfo](/api-reference/CloudNimble/Text/Xml/Serialization/XmlTypeInfo) and then goes through one of the internal
`Read` or `Write` methods in this file. All reading is done by [Utf8XmlReader](/api-reference/CloudNimble/Text/Xml/Utf8XmlReader) and
all writing by [Utf8XmlWriter](/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter).

## Examples

The following examples come from the serialization samples, and each shows the output the code produces.

### Serialize an object graph with indentation

```csharp
var invoice = new Invoice
{
    Number = 7,
    BillTo = new InvoiceCustomer { Name = "Contoso", Email = "ap@contoso.example" },
    Lines =
    [
        new InvoiceLine { Sku = "KB-101", Quantity = 2 },
        new InvoiceLine { Sku = "MS-220", Quantity = 1 },
    ],
};

var options = new XmlSerializerOptions { WriteIndented = true, NewLine = "\n" };

string xml = XmlSerializer.Serialize(invoice, options);
output.WriteLine(xml);
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Invoice>
  <Number>7</Number>
  <BillTo>
    <Name>Contoso</Name>
    <Email>ap@contoso.example</Email>
  </BillTo>
  <Lines>
    <Sku>KB-101</Sku>
    <Quantity>2</Quantity>
  </Lines>
  <Lines>
    <Sku>MS-220</Sku>
    <Quantity>1</Quantity>
  </Lines>
</Invoice>
```

### Serialize to UTF-8 bytes

```csharp
var customer = new InvoiceCustomer { Name = "Contoso", Email = "ap@contoso.example" };

byte[] utf8 = XmlSerializer.SerializeToUtf8Bytes(customer);

output.WriteLine($"{utf8.Length} bytes");
output.WriteLine(Encoding.UTF8.GetString(utf8));
```

The code produces the following output:

```text
126 bytes
<?xml version="1.0" encoding="utf-8"?><InvoiceCustomer><Name>Contoso</Name><Email>ap@contoso.example</Email></InvoiceCustomer>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/06_SerializeToXml.cs)

### Deserialize from a string

```csharp
const string xml = """
    <?xml version="1.0" encoding="utf-8"?>
    <PurchaseOrder>
      <Id>1042</Id>
      <Customer>Contoso</Customer>
      <Placed>2026-03-14</Placed>
      <Total>129.90</Total>
    </PurchaseOrder>
    """;

PurchaseOrder? order = XmlSerializer.Deserialize<PurchaseOrder>(xml);

output.WriteLine($"Order {order!.Id} for {order.Customer}");
output.WriteLine($"Placed {order.Placed:yyyy-MM-dd}");
output.WriteLine($"Total is 129.90: {order.Total == 129.90m}");
```

The code produces the following output:

```text
Order 1042 for Contoso
Placed 2026-03-14
Total is 129.90: True
```

### Handle XML that doesn't fit the type

```csharp
string[] documents =
[
    "<Order><Id>1042</Id></Order>",
    "<PurchaseOrder><Id>1042</PurchaseOrder>",
    "<PurchaseOrder><Id>ten</Id></PurchaseOrder>",
];

foreach (string xml in documents)
{
    try
    {
        XmlSerializer.Deserialize<PurchaseOrder>(xml);
    }
    catch (XmlException ex)
    {
        output.WriteLine(ex.Message);
    }
}
```

The code produces the following output:

```text
The root element does not match 'PurchaseOrder'.
End tag does not match start tag.
The value is not a valid integer.
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/07_DeserializeFromXml.cs)

## Best Practices

- **Reuse the options.** Keep one `XmlSerializerOptions` instance in a `static readonly` field and pass it to every call. The type metadata is cached on the instance. See [Configure XmlSerializerOptions](/guides/configure-options).
- **Write UTF-8 when the destination is bytes.** Use `SerializeToUtf8Bytes` or the `IBufferWriter<byte>` and `Stream` overloads instead of creating a `string` and encoding it. Read UTF-8 with the `ReadOnlySpan<byte>` and `Stream` overloads for the same reason.
- **Pass a `Type` when you hold an `object`.** `Serialize(value, value.GetType(), options)` serializes the run-time type. `Serialize<object>(value)` throws a `NotSupportedException`.
- **Use the source-generation overloads for trimmed and Native AOT applications.** The overloads that take an `XmlTypeInfo<TValue>` or an `XmlSerializerContext` don't use reflection. See [Use source generation](/guides/source-generation).
- **Tighten the options for XML you don't control.** Start from `XmlSerializerOptions.Strict` and set `MaxDocumentByteCount`. See [Security](/guides/security).
- **Dispose what `SerializeToDocument` returns.** The `XmlDocument` holds pooled memory.
- **Catch `XmlException` around `Deserialize`.** It reports XML that isn't well formed, values that can't be converted, missing required members, and unmapped members when those are disallowed.

## Patterns

`XmlSerializer` works together with the reader, the writer, and the document types, so an object can be one part of a larger XML document.

### Embed serialized objects in a document you write yourself

Open a [`Utf8XmlWriter`](/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter), write the parts that aren't objects, and let the serializer write each object as one element.

```csharp
var buffer = new ArrayBufferWriter<byte>();
var writerOptions = new XmlWriterOptions { Indented = true, NewLine = "\n" };

using (var writer = new Utf8XmlWriter(buffer, writerOptions))
{
    writer.WriteStartElement("Customers");
    XmlSerializer.Serialize(writer, new InvoiceCustomer { Name = "Contoso", Email = "ap@contoso.example" });
    XmlSerializer.Serialize(writer, new InvoiceCustomer { Name = "Fabrikam", Email = "billing@fabrikam.example" });
    writer.WriteEndElement();
}

output.WriteLine(Encoding.UTF8.GetString(buffer.WrittenSpan));
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Customers>
  <InvoiceCustomer>
    <Name>Contoso</Name>
    <Email>ap@contoso.example</Email>
  </InvoiceCustomer>
  <InvoiceCustomer>
    <Name>Fabrikam</Name>
    <Email>billing@fabrikam.example</Email>
  </InvoiceCustomer>
</Customers>
```

### Deserialize the interesting elements of a large document

Walk the document with a [`Utf8XmlReader`](/api-reference/CloudNimble/Text/Xml/Utf8XmlReader) and hand the serializer only the elements you want as objects. The reader is left on the end tag of the element that was read.

```csharp
ReadOnlySpan<byte> utf8 = """
    <Customers exported="2026-03-14">
      <InvoiceCustomer><Name>Contoso</Name><Email>ap@contoso.example</Email></InvoiceCustomer>
      <InvoiceCustomer><Name>Fabrikam</Name><Email>billing@fabrikam.example</Email></InvoiceCustomer>
    </Customers>
    """u8;

var reader = new Utf8XmlReader(utf8);
while (reader.Read())
{
    if (reader.TokenType is XmlTokenType.StartElement && reader.LocalNameEquals("InvoiceCustomer"u8))
    {
        InvoiceCustomer? customer = XmlSerializer.Deserialize<InvoiceCustomer>(ref reader);
        output.WriteLine($"{customer!.Name} <{customer.Email}>");
    }
}
```

The code produces the following output:

```text
Contoso <ap@contoso.example>
Fabrikam <billing@fabrikam.example>
```

### Query first, then map

Parse with [`XmlDocument`](/api-reference/CloudNimble/Text/Xml/XmlDocument), find an element, and deserialize that element.

```csharp
const string xml = """
    <Response status="ok">
      <InvoiceCustomer><Name>Contoso</Name><Email>ap@contoso.example</Email></InvoiceCustomer>
    </Response>
    """;

using XmlDocument document = XmlDocument.Parse(xml);
XmlElement element = document.RootElement.GetChild("InvoiceCustomer");

InvoiceCustomer? customer = XmlSerializer.Deserialize<InvoiceCustomer>(element);

output.WriteLine($"{customer!.Name} <{customer.Email}>");
```

The code produces the following output:

```text
Contoso <ap@contoso.example>
```

## Considerations

Keep the following in mind when you choose overloads and when you compare `XmlSerializer` with the serializers you already know.

### Reflection and trimming

The overloads that take `XmlSerializerOptions` find members and constructors through reflection. They are annotated with `RequiresUnreferencedCode` and `RequiresDynamicCode`, so the compiler warns when a trimmed or Native AOT application calls them. The overloads that take an `XmlTypeInfo<TValue>` or an `XmlSerializerContext` aren't annotated. `XmlSerializer.IsReflectionEnabledByDefault` reports whether options with no resolver fall back to reflection. When it is `false` and no resolver is set, the reflection overloads throw an `InvalidOperationException`.

### Cost of the first call

The first call for a type with a given options instance builds the type's XML mapping. In the library's benchmark of a customer object with two addresses and 20 line items, that first write takes 612,933 ns and allocates 75,440 bytes. Later writes with the same options take 1,710 ns and allocate nothing. The cached `System.Xml.Serialization.XmlSerializer` takes 4,089 ns and allocates 8,648 bytes for the same object, and `System.Text.Json` takes 1,502 ns for the equivalent JSON. See [Benchmarks](/benchmarks).

### Buffering

- `Serialize` to a `string` or a `byte[]`, and `SerializeAsync` to a `Stream`, build the whole document in a pooled buffer first. `SerializeAsync` then writes it to the stream in one asynchronous write.
- `Deserialize` and `DeserializeAsync` from a `Stream` or a `PipeReader` read to the end into a pooled buffer before parsing. `MaxDocumentByteCount` limits how much is read.
- `Deserialize` from an `XmlElement` or an `XmlNode` writes that element to a pooled buffer and reads it back.
- To process a large document without holding it all in memory, use `SerializeAsyncEnumerable` and `DeserializeAsyncEnumerable`. See [Streaming](/guides/streaming).

### Differences from System.Text.Json

- `Serialize<object>(value)` doesn't serialize the run-time type. It throws a `NotSupportedException`. Use the overload that takes a `Type`.
- Constructor parameters are matched to members with case unless `PropertyNameCaseInsensitive` is `true`. See [Immutable types](/guides/immutable-types).
- `RespectRequiredConstructorParameters` defaults to `true`.
- A `null` member is written as an element marked `xsi:nil="true"` by default, because XML has no `null` literal.
- A collection is written as repeated elements, and a document has exactly one root element.

### Differences from System.Xml.Serialization.XmlSerializer

- There is no instance to construct and cache per type.
- Only the attributes in `CloudNimble.Text.Xml.Serialization` are read. Attributes from `System.Xml.Serialization`, `IXmlSerializable`, and data contract attributes are ignored.
- Collections have no wrapper element unless you add `[XmlArray]`.
- Input and output are UTF-8. The library doesn't reference `System.Xml`.

See [Migrate from XmlSerializer](/guides/migrate/from-xmlserializer).

### Exceptions

`Deserialize` throws an [`XmlException`](/api-reference/CloudNimble/Text/Xml/XmlException) for XML that isn't well formed and for XML that doesn't satisfy the type. A type whose mapping is not valid, such as one with `[XmlAttribute]` on an object member or with two members that share an element name, throws a `NotSupportedException` or an `InvalidOperationException` the first time the type is used, for serializing as well as deserializing.

### Thread safety

The methods are static and keep no state between calls. See [Thread safety](/guides/thread-safety).
