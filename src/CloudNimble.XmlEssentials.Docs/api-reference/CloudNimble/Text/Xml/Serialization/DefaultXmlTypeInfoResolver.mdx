## Summary

Defines the default, reflection-based XML contract resolver used by [XmlSerializer](/api-reference/CloudNimble/Text/Xml/XmlSerializer). This class cannot be inherited.

## Usage

`DefaultXmlTypeInfoResolver` is the resolver behind every `XmlSerializer` call that passes only a value, or a value and options. It finds the converter for a type and wraps it in type info. For a class or struct, that converter is built by inspecting the type's members and attributes with reflection.

You rarely name the class. An `XmlSerializerOptions` instance with no `TypeInfoResolver` uses the shared `DefaultXmlTypeInfoResolver.Instance`:

```csharp
var receipt = new Receipt { Number = 77, Paid = 129.90m };
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };

string xml = XmlSerializer.Serialize(receipt, options);
output.WriteLine(xml);

Receipt? copy = XmlSerializer.Deserialize<Receipt>(xml, options);
output.WriteLine($"Receipt {copy!.Number}: {copy.Paid}");
output.WriteLine(options.TypeInfoResolver!.GetType().Name);
```

The code produces the following output:

```text
<Receipt><Number>77</Number><Paid>129.90</Paid></Receipt>
Receipt 77: 129.90
DefaultXmlTypeInfoResolver
```

The resolver looks for a converter in this order: the `Converters` list of the options, then `[XmlConverter]` on the type, then the built-in converters. It returns `null` when none of them handles the type.

The class has no public constructor. Use `Instance`. It's the counterpart of `DefaultJsonTypeInfoResolver` in System.Text.Json.

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/31_ReflectionVsSourceGeneration.cs)

## Remarks

The resolver builds type info from the converters of an [XmlSerializerOptions](/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions) instance: its
[XmlSerializerOptions.Converters](/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions#converters), the [XmlConverterAttribute](/api-reference/CloudNimble/Text/Xml/Serialization/XmlConverterAttribute) on the type, and the built-in converters.

## Considerations

- **It isn't safe for trimming or Native AOT.** The resolver reads members with reflection and creates generic converter types at run time. In such an application, use a source-generated context, and set the `IsReflectionEnabledByDefault` switch to `false` so that options stop falling back to this resolver. See [Publish with Native AOT](/guides/native-aot).
- **The first request for a type is the expensive one.** On the repository's graph benchmark, a first read through a new options instance takes 594,483 ns and allocates 78,608 B, against 3,358 ns and 3,168 B for later reads. Create one `XmlSerializerOptions` instance and reuse it, because the options cache what the resolver returns.
- **There are no modifiers.** `DefaultJsonTypeInfoResolver` in System.Text.Json lets you add modifiers that edit a contract. This class has none. Change a mapping with attributes, options, or a custom converter.
- **Generated contexts use it too.** A context in metadata mode gets all its type info here, and a context in any mode uses it for a type the context doesn't list.
- **It's stateless and shared.** `Instance` is safe to use from any thread. The caching is done by the options, not by the resolver.
