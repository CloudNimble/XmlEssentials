In this article, you learn how to serialize a member whose runtime type is a class derived from its declared type, and how to get the same derived type back when you deserialize. You need this whenever a property, a list, or the document root is declared as a base class.

The model follows System.Text.Json: you opt in on the base type, and you list every derived type that is allowed. `[XmlPolymorphic]` and `[XmlDerivedType<T>]` play the roles of `[JsonPolymorphic]` and `[JsonDerivedType]`. The difference is where the type name goes. JSON needs a `$type` property. XML already has a place for it: the name of the element.

<Note>
The examples on this page use the reflection-based serializer. A source-generated context reads and writes derived types in the same way. List the base type on the context, and the generator includes the derived types that `[XmlDerivedType<T>]` names. See [Source generation](/guides/source-generation).
</Note>

## Serialize the declared type only

Without any attributes, the serializer writes the members of the declared type and nothing else. A derived class that isn't declared is not written by accident. This is the same default as System.Text.Json, and it prevents a derived type from exposing data that the contract never mentioned.

## Declare the derived types

To opt in, put [`[XmlPolymorphic]`](/api-reference/CloudNimble/Text/Xml/Serialization/XmlPolymorphicAttribute) on the base type and one [`[XmlDerivedType<T>]`](/api-reference/CloudNimble/Text/Xml/Serialization/XmlDerivedTypeAttribute) for each derived type. By default, each derived type is written under an element named after it. Pass a string to choose another name.

```csharp Product.cs
[XmlPolymorphic]
[XmlDerivedType<Book>]
[XmlDerivedType<Dvd>("Disc")]
public class Product
{
    public string? Title { get; set; }
}

public class Book : Product
{
    public string? Author { get; set; }
}

public sealed class Dvd : Product
{
    public int Runtime { get; set; }
}

public sealed class Catalog
{
    public List<Product> Products { get; set; } = [];
}
```

```csharp Program.cs
var options = new XmlSerializerOptions { WriteIndented = true, NewLine = "\n" };
var catalog = new Catalog
{
    Products =
    [
        new Book { Title = "Clean Code", Author = "Robert C. Martin" },
        new Dvd { Title = "The Matrix", Runtime = 136 },
        new Product { Title = "Gift card" },
    ],
};

string xml = XmlSerializer.Serialize(catalog, options);
output.WriteLine(xml);

Catalog? copy = XmlSerializer.Deserialize<Catalog>(xml, options);
foreach (Product product in copy!.Products)
{
    output.WriteLine($"{product.GetType().Name}: {product.Title}");
}
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Catalog>
  <Book>
    <Title>Clean Code</Title>
    <Author>Robert C. Martin</Author>
  </Book>
  <Disc>
    <Title>The Matrix</Title>
    <Runtime>136</Runtime>
  </Disc>
  <Products>
    <Title>Gift card</Title>
  </Products>
</Catalog>
Book: Clean Code
Dvd: The Matrix
Product: Gift card
```

Notice the following:

- The element name is the discriminator. `<Book>` becomes a `Book` and `<Disc>` becomes a `Dvd`, with every member of the derived type.
- An object of the base type itself is written under the member's own name, `<Products>`, and is read back as a `Product`.
- The naming policy for elements applies to a discriminator that is used as an element name. With `PropertyNamingPolicy = XmlNamingPolicy.CamelCase`, `Book` is written as `<book>`.
- A discriminator can't be the element name of another member of the containing type. If two members could claim the same element name, the serializer throws an `InvalidOperationException` when it first builds the type's metadata. Give each derived type its own discriminator.

`[XmlDerivedType<T>]` is a generic attribute, so the derived type is checked by the compiler. The discriminator is always a string. There is no integer form.

The declared base type can be a concrete class, an abstract class, or an interface. An abstract class or an interface must list its derived types with `[XmlDerivedType<T>]`, because the serializer can't create the declared type itself:

- When reading, an element that doesn't identify a derived type throws `XmlException`. A concrete base class would be created instead.
- When writing, a value whose type isn't listed throws `NotSupportedException`, unless the base type sets `UnknownDerivedTypeHandling`.
- An abstract class or an interface with no `[XmlDerivedType<T>]` isn't supported, and the serializer throws `NotSupportedException` with the message `The type '...' is not supported.`

## Choose where the discriminator is written

Set `XmlPolymorphicAttribute.DiscriminatorPlacement` to one of the [`XmlDiscriminatorPlacement`](/api-reference/CloudNimble/Text/Xml/XmlDiscriminatorPlacement) values.

| Placement | The derived type is identified by | Example |
| --- | --- | --- |
| `ElementName` (default) | The name of the element | `<Book>...</Book>` |
| `Attribute` | An attribute that you name with `TypeDiscriminatorPropertyName` | `<Payment kind="card">...</Payment>` |
| `XsiType` | The `xsi:type` attribute from XML Schema | `<Vehicle xsi:type="Truck">...</Vehicle>` |

Use an attribute when the element name must stay the same for every derived type, for example because a schema fixes it.

### Use an attribute

With `XmlDiscriminatorPlacement.Attribute`, `TypeDiscriminatorPropertyName` is required. The string you pass to `[XmlDerivedType<T>]` is the attribute's value.

```csharp Payment.cs
[XmlPolymorphic(DiscriminatorPlacement = XmlDiscriminatorPlacement.Attribute, TypeDiscriminatorPropertyName = "kind")]
[XmlDerivedType<CardPayment>("card")]
[XmlDerivedType<BankTransfer>("transfer")]
public class Payment
{
    public decimal Amount { get; set; }
}

public sealed class CardPayment : Payment
{
    public string? LastFour { get; set; }
}

public sealed class BankTransfer : Payment
{
    public string? Reference { get; set; }
}

public sealed class Checkout
{
    public int OrderId { get; set; }

    public Payment? Payment { get; set; }
}
```

```csharp Program.cs
var options = new XmlSerializerOptions { WriteIndented = true, NewLine = "\n" };
var checkout = new Checkout
{
    OrderId = 1042,
    Payment = new CardPayment { Amount = 59.90m, LastFour = "4242" },
};

string xml = XmlSerializer.Serialize(checkout, options);
output.WriteLine(xml);

Checkout? copy = XmlSerializer.Deserialize<Checkout>(xml, options);
output.WriteLine(copy!.Payment!.GetType().Name);

try
{
    XmlSerializer.Deserialize<Checkout>(
        """<Checkout><OrderId>1042</OrderId><Payment kind="voucher"><Amount>5</Amount></Payment></Checkout>""");
}
catch (XmlException ex)
{
    output.WriteLine(ex.Message);
}
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Checkout>
  <OrderId>1042</OrderId>
  <Payment kind="card">
    <Amount>59.90</Amount>
    <LastFour>4242</LastFour>
  </Payment>
</Checkout>
CardPayment
Unknown type discriminator 'voucher'.
```

The last line shows the default when a document names a discriminator that the base type doesn't declare: an `XmlException`. An element with no discriminator attribute at all is read as the declared type.

The discriminator attribute can appear anywhere in the start tag. Unlike a JSON `$type` property, it never has to come first, because the serializer sees every attribute of an element before it reads the element's content.

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/16_Polymorphism.cs)

### Use xsi:type

`XmlDiscriminatorPlacement.XsiType` writes the discriminator as `xsi:type`, the attribute that XML Schema defines for this purpose and that `System.Xml.Serialization.XmlSerializer` also writes. The value is the discriminator string exactly as you declared it. The serializer doesn't write or resolve a namespace prefix inside the value. The next example uses this placement.

## Handle a type that isn't declared

A runtime type that the base type doesn't declare is rejected by default. `Ebook` derives from `Book`, but `Product` doesn't list it:

```csharp Program.cs
var catalog = new Catalog
{
    Products = [new Ebook { Title = "Refactoring", Author = "Martin Fowler", Format = "EPUB" }],
};

try
{
    XmlSerializer.Serialize(catalog);
}
catch (NotSupportedException ex)
{
    output.WriteLine(ex.Message);
}
```

The code produces the following output:

```text
The type 'CloudNimble.XmlEssentials.Samples.Models.Shapes.Ebook' is not a declared derived type of 'CloudNimble.XmlEssentials.Samples.Models.Shapes.Product'.
```

To accept such a type, set `XmlPolymorphicAttribute.UnknownDerivedTypeHandling` to one of the [`XmlUnknownDerivedTypeHandling`](/api-reference/CloudNimble/Text/Xml/Serialization/XmlUnknownDerivedTypeHandling) values.

| Value | When writing a type that isn't declared | When reading a discriminator that isn't declared |
| --- | --- | --- |
| `FailSerialization` (default) | Throws `NotSupportedException`. | Throws `XmlException`. |
| `FallBackToBaseType` | Writes the object as the declared base type. | Reads the element as the declared base type. |
| `FallBackToNearestAncestor` | Writes the object as the closest base class that is declared, or as the declared base type if none is. | Reads the element as the declared base type. |

The following hierarchy uses `xsi:type` and falls back to the nearest ancestor. `SportsCar` derives from `Car` and isn't declared.

```csharp Vehicle.cs
[XmlPolymorphic(DiscriminatorPlacement = XmlDiscriminatorPlacement.XsiType, UnknownDerivedTypeHandling = XmlUnknownDerivedTypeHandling.FallBackToNearestAncestor)]
[XmlDerivedType<Car>]
[XmlDerivedType<Truck>]
public class Vehicle
{
    public string? Make { get; set; }
}

public class Car : Vehicle
{
    public int Doors { get; set; }
}

public sealed class Truck : Vehicle
{
    public int Payload { get; set; }
}

public sealed class SportsCar : Car
{
    public int TopSpeed { get; set; }
}
```

```csharp Program.cs
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };

Vehicle truck = new Truck { Make = "Northwind", Payload = 12000 };
output.WriteLine(XmlSerializer.Serialize(truck, options));

Vehicle sportsCar = new SportsCar { Make = "Contoso", Doors = 2, TopSpeed = 310 };
string xml = XmlSerializer.Serialize(sportsCar, options);
output.WriteLine(xml);

Vehicle? copy = XmlSerializer.Deserialize<Vehicle>(xml, options);
output.WriteLine(copy!.GetType().Name);
```

The code produces the following output:

```text
<Vehicle xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:type="Truck"><Make>Northwind</Make><Payload>12000</Payload></Vehicle>
<Vehicle xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:type="Car"><Make>Contoso</Make><Doors>2</Doors></Vehicle>
Car
```

The `SportsCar` is written as a `Car`. Its `TopSpeed` isn't written, and the document reads back as a `Car`. A fallback loses the members of the undeclared type, so choose it only when that loss is acceptable.

This example also shows a polymorphic document root: the variable is declared as `Vehicle`, so the root element is `<Vehicle>` and the attribute names the derived type.

<Note>
With `XmlDiscriminatorPlacement.ElementName`, an element whose name isn't declared doesn't reach the polymorphism logic at all. Inside an object, it is content that no member maps, and [`UnmappedMemberHandling`](/guides/mixed-content#keep-content-that-no-member-maps) decides whether it is skipped or rejected. At the document root, it is an `XmlException` because the root name doesn't match.
</Note>

## Mind the type you serialize as

The serializer uses the type you declare, not the runtime type, to choose the document element. The next example serializes the same `CardPayment` three ways: as `Payment`, as its own type through type inference, and as its runtime type through the overload that takes a `Type`.

```csharp Program.cs
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };
var card = new CardPayment { Amount = 59.90m, LastFour = "4242" };

output.WriteLine(XmlSerializer.Serialize<Payment>(card, options));
output.WriteLine(XmlSerializer.Serialize(card, options));
output.WriteLine(XmlSerializer.Serialize(card, card.GetType(), options));
```

The code produces the following output:

```xml
<Payment kind="card"><Amount>59.90</Amount><LastFour>4242</LastFour></Payment>
<CardPayment kind="card"><Amount>59.90</Amount><LastFour>4242</LastFour></CardPayment>
<CardPayment kind="card"><Amount>59.90</Amount><LastFour>4242</LastFour></CardPayment>
```

A derived type inherits the polymorphism attributes of its base type, so the discriminator is written even when you serialize the derived type directly. System.Text.Json leaves the discriminator out in that case. Read a document with the same type argument that wrote it: a document written as `Payment` has a `<Payment>` root, and `Deserialize<CardPayment>` expects `<CardPayment>`.

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/16_Polymorphism.cs)

## XmlInclude is not for derived types

If you come from `System.Xml.Serialization`, you know `[XmlInclude(typeof(Book))]` as the way to declare a known derived type. In XmlEssentials that job belongs to `[XmlDerivedType<T>]`.

[`[XmlInclude]`](/api-reference/CloudNimble/Text/Xml/Serialization/XmlIncludeAttribute) in this library is the counterpart of `[JsonInclude]`: it goes on a property or field that isn't public, and opts that member in to serialization.

```csharp Account.cs
public sealed class Account
{
    public string? Name { get; set; }

    [XmlInclude]
    internal string? LedgerCode { get; set; }
}
```

```csharp Program.cs
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };
var account = new Account { Name = "Operations", LedgerCode = "OPS-17" };

output.WriteLine(XmlSerializer.Serialize(account, options));
```

The code produces the following output:

```xml
<Account><Name>Operations</Name><LedgerCode>OPS-17</LedgerCode></Account>
```

## Infer the derived types of a closed type

A closed type is a class declared with the `closed` modifier, which needs C# 15 and .NET 11. Every type that derives from it is in its own assembly, and the compiler lists them. Set `InferClosedTypePolymorphism` and the serializer takes the derived types from that list, so you don't write an `[XmlDerivedType<T>]` for each one.

```csharp
public closed class Notification
{
    public string? Text { get; set; }
}

public sealed class EmailNotification : Notification
{
    public string? Address { get; set; }
}

public sealed class SmsNotification : Notification
{
    public string? Number { get; set; }
}

public sealed class Outbox
{
    [XmlArray]
    public List<Notification> Messages { get; set; } = [];
}
```

```csharp
var options = new XmlSerializerOptions
{
    InferClosedTypePolymorphism = true,
    NewLine = "\n",
    OmitXmlDeclaration = true,
    WriteIndented = true,
};
var outbox = new Outbox
{
    Messages =
    {
        new EmailNotification { Text = "Your order shipped.", Address = "ada@example.com" },
        new SmsNotification { Text = "Your code is 4242.", Number = "+1 555 0100" },
    },
};

string xml = XmlSerializer.Serialize(outbox, options);
output.WriteLine(xml);

Outbox? copy = XmlSerializer.Deserialize<Outbox>(xml, options);
foreach (Notification message in copy!.Messages)
{
    output.WriteLine(message.GetType().Name);
}
```

The code produces the following output:

```text
<Outbox>
  <Messages>
    <EmailNotification>
      <Text>Your order shipped.</Text>
      <Address>ada@example.com</Address>
    </EmailNotification>
    <SmsNotification>
      <Text>Your code is 4242.</Text>
      <Number>+1 555 0100</Number>
    </SmsNotification>
  </Messages>
</Outbox>
EmailNotification
SmsNotification
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/16_Polymorphism.cs)

The rules are those of `InferClosedTypePolymorphism` in System.Text.Json:

- The discriminator of a derived type is its name. For a generic type that is the name without its type arguments. It goes through the naming policy, and it is written where `DiscriminatorPlacement` says, as a declared discriminator is.
- A derived type that is closed itself can't be created, so the types that derive from it are used in its place.
- `[XmlPolymorphic(InferClosedTypePolymorphism = true)]` on a type infers for that type whatever the options say, and `false` turns it off for that type.
- A type that declares a derived type with `[XmlDerivedType<T>]` has nothing inferred. What it declares is the whole list.
- `[XmlPolymorphic(InferClosedTypePolymorphism = true)]` on a type that isn't closed throws an `InvalidOperationException` the first time the type is used.
- A closed type whose derived types aren't inferred, and that declares none, isn't supported: `XmlSerializer` throws a `NotSupportedException`.

A source-generated context lists the derived types of a closed type, so the same options work with it.

## What isn't supported

- **Members of type `object`.** A member declared as `object` is written as the type its value has, with no discriminator, so the document doesn't say which type wrote it. It is read back as an `XmlElement`, which you can read as the type you expect with `XmlSerializer.Deserialize<T>(element)`. Set `UnknownTypeHandling` to `XmlUnknownTypeHandling.XmlNode` to read an `XmlNode` you can change instead. To get the derived type back when reading, declare the member as a base type with `[XmlDerivedType]`.
- **Configuring polymorphism at run time.** The attributes are the only way to declare derived types. There is no contract-customization API for it.
