## Summary

Options for [Utf8XmlWriter](/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter).

## Usage

Create the options, set the properties you need, and pass the value to a `Utf8XmlWriter` constructor, as in `new Utf8XmlWriter(buffer, options)`. A writer keeps its options for its whole life, including across `Reset`.

```csharp
var buffer = new ArrayBufferWriter<byte>();
var options = new XmlWriterOptions { Indented = true, NewLine = "\n" };
```

The properties fall into four groups:

| Group | Properties |
| --- | --- |
| Formatting | `Indented`, `IndentSize`, `IndentCharacter`, `NewLine` |
| The start of the document | `OmitXmlDeclaration`, `Standalone`, `Version`, `EmitByteOrderMark` |
| Checks | `SkipValidation` |
| Limits | `MaxDepth`, `MaxAttributeCount`, `MaxNameByteCount` |

With no options at all, the writer produces one line of XML that starts with an XML 1.0 declaration, with validation on.

## Remarks

A max-* of 0 means the default from the DoS table. Construct with
`new XmlWriterOptions()` so indent defaults apply.

## Examples

Each example is a sample in the repository whose output is checked by a test.

### Indentation

`WriteParagraph` writes the same small document with the options it's given.

```csharp
output.WriteLine("Not indented:");
output.WriteLine(WriteParagraph(new XmlWriterOptions { OmitXmlDeclaration = true }));

output.WriteLine("Indented:");
output.WriteLine(WriteParagraph(new XmlWriterOptions { OmitXmlDeclaration = true, Indented = true, NewLine = "\n" }));

output.WriteLine("Indented with four spaces:");
output.WriteLine(WriteParagraph(new XmlWriterOptions { OmitXmlDeclaration = true, Indented = true, IndentSize = 4, NewLine = "\n" }));
```

```text
Not indented:
<Order><Item><Name>Keyboard</Name></Item><Note>Leave with **Ada** only.</Note></Order>
Indented:
<Order>
  <Item>
    <Name>Keyboard</Name>
  </Item>
  <Note>Leave with **Ada** only.</Note>
</Order>
Indented with four spaces:
<Order>
    <Item>
        <Name>Keyboard</Name>
    </Item>
    <Note>Leave with **Ada** only.</Note>
</Order>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/24_WriteNamespacesAndMarkup.cs)

### The XML declaration

`WriteOrder` writes one empty element with the options it's given.

```csharp
output.WriteLine(WriteOrder(new XmlWriterOptions()));
output.WriteLine(WriteOrder(new XmlWriterOptions { OmitXmlDeclaration = true }));
output.WriteLine(WriteOrder(new XmlWriterOptions { Standalone = true }));
output.WriteLine(WriteOrder(new XmlWriterOptions { Version = XmlVersion.Version11 }));

var buffer = new ArrayBufferWriter<byte>();
using (var writer = new Utf8XmlWriter(buffer, new XmlWriterOptions { EmitByteOrderMark = true }))
{
    writer.WriteEmptyElement("Order");
}

output.WriteLine($"With a byte order mark, the output starts with: {Convert.ToHexString(buffer.WrittenSpan[..3])}");
```

```text
<?xml version="1.0" encoding="utf-8"?><Order/>
<Order/>
<?xml version="1.0" encoding="utf-8" standalone="yes"?><Order/>
<?xml version="1.1" encoding="utf-8"?><Order/>
With a byte order mark, the output starts with: EFBBBF
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/24_WriteNamespacesAndMarkup.cs)

## Best Practices

- **Set `NewLine` when the bytes matter.** The default is `Environment.NewLine`, which differs between Windows and Linux. Choose `"\n"` or `"\r\n"` when the output is compared, hashed, signed, or checked in.
- **Don't indent output that only programs read.** Indentation makes the output larger and changes nothing a parser cares about.
- **Use `OmitXmlDeclaration` for fragments** that go inside another document or message.
- **Leave `SkipValidation` off** until a measurement shows that you need it, and then only for code whose output you test. With it on, the writer can produce XML that no reader accepts.
- **Leave `EmitByteOrderMark` off** unless a consumer asks for the byte order mark. UTF-8 doesn't need one.
- **Keep `Version` at XML 1.0** unless your data holds control characters that only XML 1.1 can carry.

## Considerations

Know the following about the defaults and what each group of options does.

### Defaults

| Property | Default |
| --- | --- |
| `Indented` | `false` |
| `IndentSize` | 0, which means 2 |
| `IndentCharacter` | A space |
| `NewLine` | `Environment.NewLine` |
| `OmitXmlDeclaration` | `false` |
| `Standalone` | `null`, which leaves `standalone` out of the declaration |
| `Version` | `XmlVersion.Version10` |
| `EmitByteOrderMark` | `false` |
| `SkipValidation` | `false` |
| `MaxDepth` | 0, which means 64 |
| `MaxAttributeCount` | 0, which means 1,000 |
| `MaxNameByteCount` | 0, which means 1,024 bytes |

### new and default behave the same

`XmlWriterOptions` is a struct. `default(XmlWriterOptions)` leaves `IndentCharacter` as the null character and `NewLine` as `null`, and the writer treats both as their documented defaults. That's why the `options` parameter of the `Utf8XmlWriter` constructors can be omitted.

### Limits

A limit of 0 selects its default. There's no value that turns a limit off. `MaxAttributeCount` includes namespace declarations, including the ones the writer adds. `MaxNameByteCount` applies to element names, attribute names, and prefixes. The writer has no limit on text or on the size of the document.

### What indentation does

`Indented` adds a line break and indentation before elements only. An element that holds text is written on one line, with any child elements, so that no value changes. Comments and processing instructions get no line break of their own.

### What SkipValidation skips

With `SkipValidation` set, the writer doesn't check names, namespace declarations, duplicate attributes, the characters of comments, CDATA sections, and processing instructions, or that every element is closed when the writer is disposed. It still escapes values, allows only one root element, and enforces `MaxDepth` and `MaxAttributeCount`.
