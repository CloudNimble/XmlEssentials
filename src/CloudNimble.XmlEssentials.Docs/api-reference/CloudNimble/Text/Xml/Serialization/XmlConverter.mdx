## Summary

Converts *T* to and from XML.

## Usage

A converter reads one type from XML and writes it back. To write your own, derive from `XmlConverter<T>` and override `Read` and `Write`. You can't derive from the non-generic `XmlConverter` class directly: it's the common base of `XmlConverter<T>` and `XmlConverterFactory`.

```csharp
public sealed class MoneyConverter : XmlConverter<Money>
{
    public override Money Read(ref Utf8XmlReader reader, Type typeToConvert, XmlSerializerOptions options)
    {
        Money value = default;
        if (reader.IsEmptyElement)
        {
            return value;
        }

        while (reader.Read() && reader.TokenType is not XmlTokenType.EndElement)
        {
            if (reader.TokenType is XmlTokenType.Text or XmlTokenType.CData)
            {
                value = Parse(reader.GetString()!);
            }
        }

        return value;
    }

    public override void Write(Utf8XmlWriter writer, Money value, XmlSerializerOptions options)
    {
        writer.WriteStringValue(string.Create(CultureInfo.InvariantCulture, $"{value.Amount:0.00} {value.Currency}"));
    }

    private static Money Parse(string text)
    {
        int space = text.IndexOf(' ');
        if (space < 0 || !decimal.TryParse(text.AsSpan(0, space), NumberStyles.Number, CultureInfo.InvariantCulture, out decimal amount))
        {
            throw new XmlException($"'{text}' is not an amount followed by a currency code.");
        }

        return new Money(amount, text[(space + 1)..]);
    }
}
```

Register the converter by adding an instance to `XmlSerializerOptions.Converters`, or by naming it in `[XmlConverter]` on the type it converts.

### Where Read starts and stops

`Read` is called with the reader on the start tag of the element that holds the value. It must leave the reader on the last token of that element: the end tag, or the start tag itself when the element is an empty-element tag such as `<Total/>`, which has no end-tag token. Check `reader.IsEmptyElement` before the first call to `reader.Read()`.

### What Write writes

`Write` is called after the serializer has written the element's start tag. Write the content, text or child elements, and return. The serializer writes the end tag.

The classes correspond to `JsonConverter` and `JsonConverter<T>` in System.Text.Json. For the factory pattern, registration, and attribute support, see [How to write custom converters](/guides/custom-converters).

## Examples

### Register converters in the options

The following example registers `MoneyConverter` and a second converter that replaces the built-in converter of `DateOnly`. `Issued` is mapped as an attribute, so it's written by the date converter's `WriteAsAttribute` method.

```csharp
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };
options.Converters.Add(new MoneyConverter());
options.Converters.Add(new CompactDateConverter());

var invoice = new Invoice
{
    Number = "INV-204",
    Issued = new DateOnly(2026, 11, 23),
    Due = new DateOnly(2026, 12, 23),
    Total = new Money(129.9m, "USD"),
};

string xml = XmlSerializer.Serialize(invoice, options);
output.WriteLine(xml);

Invoice? copy = XmlSerializer.Deserialize<Invoice>(xml, options);
output.WriteLine($"{copy!.Number}: {copy.Total.Amount} {copy.Total.Currency}, issued {copy.Issued:yyyy-MM-dd}, due {copy.Due:yyyy-MM-dd}");
```

The code produces the following output:

```text
<Invoice Issued="20261123"><Due>20261223</Due><Number>INV-204</Number><Total>129.90 USD</Total></Invoice>
INV-204: 129.90 USD, issued 2026-11-23, due 2026-12-23
```

### Convert a built-in type in elements, attributes, and text

```csharp
public sealed class CompactDateConverter : XmlConverter<DateOnly>
{
    private const string Format = "yyyyMMdd";

    public override DateOnly Read(ref Utf8XmlReader reader, Type typeToConvert, XmlSerializerOptions options)
    {
        DateOnly value = default;
        if (reader.IsEmptyElement)
        {
            return value;
        }

        while (reader.Read() && reader.TokenType is not XmlTokenType.EndElement)
        {
            if (reader.TokenType is XmlTokenType.Text)
            {
                value = ReadLexical(reader.ValueSpan, options);
            }
        }

        return value;
    }

    public override DateOnly ReadAsAttribute(ref Utf8XmlReader reader, Type typeToConvert, XmlSerializerOptions options)
    {
        return ReadLexical(reader.ValueSpan, options);
    }

    public override DateOnly ReadLexical(ReadOnlySpan<byte> utf8, XmlSerializerOptions options)
    {
        string text = Encoding.UTF8.GetString(utf8);
        return DateOnly.TryParseExact(text, Format, CultureInfo.InvariantCulture, DateTimeStyles.None, out DateOnly value)
            ? value
            : throw new XmlException($"'{text}' is not a date in the form {Format}.");
    }

    public override void Write(Utf8XmlWriter writer, DateOnly value, XmlSerializerOptions options)
    {
        writer.WriteStringValue(value.ToString(Format, CultureInfo.InvariantCulture));
    }

    public override void WriteAsAttribute(Utf8XmlWriter writer, XmlName name, DateOnly value, XmlSerializerOptions options)
    {
        writer.WriteAttributeString(name.LocalName, value.ToString(Format, CultureInfo.InvariantCulture));
    }
}
```

## Best Practices

- **Check `IsEmptyElement` first in `Read`.** An empty-element tag has no end-tag token. A loop that reads until `EndElement` without the check runs into the elements that follow.
- **Leave the reader on the element's last token.** Don't read past the end tag, and don't stop before it. The serializer continues from where you stop.
- **Pass the reader by `ref` to helper methods.** `Utf8XmlReader` is a struct. A helper that takes it by value advances a copy.
- **Skip what you don't recognize.** Call `reader.Skip()` on an unknown child element so that a newer document doesn't break an older converter.
- **Close every element you open in `Write`,** and don't write the value's own start or end tag.
- **Throw `XmlException` for content that isn't valid,** as the built-in converters do.
- **Format and parse with `CultureInfo.InvariantCulture`.** XML is exchanged between machines, and the current culture changes decimal separators and date order.
- **Keep converters stateless.** One instance serves every thread that uses the options.
- **Don't widen `CanConvert` on an `XmlConverter<T>`.** A converter can serve only `T`. Use an `XmlConverterFactory` for a family of types.

## Considerations

- **Lookup order.** The serializer uses the first match among the converters in `XmlSerializerOptions.Converters`, in list order, then `[XmlConverter]` on the type, then the built-in converters.
- **Nil elements.** With `HandleNull` at its default of `false`, the serializer handles an element marked `xsi:nil="true"` itself: it returns `null` without calling `Read`, or throws `XmlException` when `T` can't be `null`. Override `HandleNull` to return `true` to receive those elements.
- **Attributes and text need more overrides.** `ReadAsAttribute`, `WriteAsAttribute`, and `ReadLexical` throw `InvalidOperationException` unless you override them. The serializer calls them only for the types it treats as simple values, such as numbers, dates, strings, and enumerations, when a member is mapped with `[XmlAttribute]`, `[XmlText]`, or `[XmlCData]`. A member of any other type can't be an attribute or text, whatever its converter writes.
- **Source generation.** A converter the generator writes in the default mode asks the options for a converter only for enumeration members. It doesn't use your converter for a class, a struct, or a built-in value. Use a context in metadata mode to apply custom converters. See [Use a converter with source generation](/guides/custom-converters#use-a-converter-with-source-generation).
- **Stream reads.** When the serializer reads from a stream and the document isn't all in memory yet, it first makes sure the whole element has arrived and then calls `Read` once. A converter never has to resume part way through an element.
- **Differences from `JsonConverter<T>`.** `Read` and `Write` work on an element, not on a token. There are no `ReadAsPropertyName` or `WriteAsPropertyName` methods. `HandleNull` concerns `xsi:nil` when reading.
