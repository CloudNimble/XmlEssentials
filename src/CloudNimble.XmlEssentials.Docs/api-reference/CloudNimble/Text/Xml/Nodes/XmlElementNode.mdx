## Usage

# Usage

`XmlElementNode` is a mutable element with `Attributes` and mixed `Children`.

```csharp
var root = new XmlElementNode("Person", namespaceUri: null, prefix: null);
root.SetAttribute("id", "1");
root.AddElement("Name").InnerText = "Ada";
Console.WriteLine(root["Name"]!.InnerText);
```

Indexers return the first child element with that local name (and optional namespace), or null.

## Examples

# Examples

Prefixed element:

```csharp
var root = new XmlElementNode("e", "urn:x", "p");
root.SetAttribute("a", "1", "urn:x");
root.ToString(); // <p:e xmlns:p="urn:x" ...>
```

## Best Practices

# Best Practices

Use `SetAttribute` instead of adding duplicate `XmlAttributeNode` instances. Remove from `Children` / `Attributes` before attaching a node to another parent.

## Patterns

# Patterns

**SetAttribute.** Replaces the value when the name (and namespace) already exists; otherwise appends.

**AddElement.** Creates a child and returns it for chaining `InnerText` or further children.

## Considerations

# Considerations

`InnerText` get walks descendant text and CDATA. Set replaces all children. `WriteTo` skips attributes named `xmlns` or prefixed `xmlns` so the writer can declare namespaces from `Prefix` and `NamespaceUri`.

`ValueKind` is always `Element` (there is no empty-element flag on the mutable node; empty vs paired end tag is decided at write time).
