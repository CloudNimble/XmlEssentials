# Doc findings resolution

Part of the [XmlEssentials spec](README.md).

The documentation pass (`681f0ac`) wrote a sample and a page for every public member, and in doing so found places where the library does not do what a reader would expect. This task records every finding, deduplicated, and tracks its resolution. The raw notes were in `review/2026-11-23-documentation-findings.md`, which is not committed; this page is the record.

## Rules for this task

- A finding is closed by a test that states the correct behavior and asserts the exact result, written before the fix ([testing](14-testing.md)).
- Every permutation of a finding is tested: each overload, each placement (root, member, wrapped item, unwrapped item), text and attribute values, XML 1.0 and XML 1.1 where the behavior touches characters.
- The documentation pass described several defects as behavior, in doc comments and guides ("The writer does not use this value"). A fix corrects those statements in the same change.
- No speed work and no benchmark runs belong to this task. The tables in [optimization](23-optimization.md) were **not** regenerated for slice 1.

## Slice 1 decisions

Each of these changes what a caller sees. They are written into the spec pages named.

1. **Interceptors apply only to a call that passes no options** ([K42](01-identity-and-decisions.md#key-decisions), [source generation](10-source-generation.md)). The old interceptor built a context around the caller's options, which is what mutated them, threw on read-only instances and bypassed their converters. Generated converters do not honor run-time options (F32), so no design that sends caller options into generated code can be correct yet. A call that passes options, even `null`, now runs exactly as written. This removes a documented behavior: `Serialize(value, options)` no longer makes a context the options' resolver. To use generated code with your own options, pass `new MyContext(options).T`.
2. **One rule names the document element** ([source generation](10-source-generation.md)). `[XmlRoot]` is read for every type info, so it now also applies to a type that a caller's own `XmlConverter<T>` writes, and to XSD-generated classes used through a context built from caller options (part of F33; not separately tested).
3. **Writer namespaces follow `System.Xml.XmlWriter`** ([XML fidelity](02-xml-fidelity.md)). A probe of `XmlWriter` settled the open question: a `null` namespace inherits, an empty string means no namespace and writes `xmlns=""` under a default namespace. The span overloads cannot say `null`, so an empty span means no namespace; the overloads with no namespace parameter inherit. A prefix that an inner element rebound is no longer reused for an unprefixed element or an attribute, and `WriteNilValue` declares `xsi` unless the `xsi` prefix itself is bound to the schema-instance namespace. The open question is removed from [open questions](20-open-questions.md).
4. **A segmented value is one kind, and nothing may interrupt it** ([writer](05-api-writer.md#segmented-values)). Mixing UTF-8 and character segments in one value was accepted before and is now rejected, as `Utf8JsonWriter` rejects it. `Write_SegmentsAndRaw` wrote such a value and now writes UTF-8 segments only.
5. **`]]>` is escaped across calls** ([writer](05-api-writer.md#segmented-values)). `WriteStringValue("]]")` followed by `WriteStringValue(">")` wrote `]]>` into character data, which is not well formed. Found while testing F8; it did not need segments.
6. **Constructor parameters match members without regard to case, always** ([object mapping](09-object-mapping.md)). `PropertyNameCaseInsensitive` now only governs names in the document. A parameter may also name a member by its XML name when the constructor is chosen, as the generator already allowed. Consequence: a type with a public parameterless constructor and a constructor whose camelCase parameters all name members is now created through the second one, because the rule "most parameters wins" did not change. `CamelCaseParameter_NextToAParameterlessConstructor_IsTheConstructorUsed` pins it; D5 asks whether the rule itself should change. A type with two public constructors of the same size whose parameters all name members, one of which matched only now, throws `NotSupportedException` asking for `[XmlConstructor]`.
7. **An abstract class or an interface must declare its derived types** ([object mapping](09-object-mapping.md#polymorphism)). With none it stays unsupported. With some, an element that identifies none of them is an `XmlException`, where a concrete base would be created.
8. **Reference handling is per object, wherever it is written** ([serializer](07-api-serializer.md)). Value types, collections, and values written by a caller's own converter are not tracked (a member written by a caller's converter was tracked before). Before, a collection that two members shared was written as a `ref` to an `id` nothing declared, which could not be read back. A caller-defined handler now writes `id` / `ref` from its own identifiers (F24).
9. **The reader's value members are empty on a start tag and an end tag.**

Permutations that were already correct, and are now pinned: a prefix in scope for another namespace is redeclared; `WriteNilValue` with `xsi` bound to another namespace; an `IgnoreCycles` or `Preserve` cycle through a member; the constructor rule for members that differ only by case; an abstract type with no derived types is rejected.

Sample tests whose expected output changed, with their samples and guides: `Sample11_ImmutableTypes_ParameterNameCase`, `Sample17_PreserveReferences_UseCustomResolver`, `Sample31_ReflectionVsSourceGeneration_Interceptors`.

One statement was removed because it could not run, and it is recorded here because the testing rules ask for a question before a gap is called unreachable. In `WriteStringValueSegment(ReadOnlySpan<byte>, bool)`, written in this slice, the branch for bytes that are not a character called `WriteStringValue(joined)` and then advanced `value`. That call always throws "Invalid UTF-8 in XML value.", so the branch now throws that exception itself. `Utf8Segments_AtEverySplit_MatchOneCall` compares the outcome with the single call for invalid and truncated input.

Hot paths changed and were not measured: element text writes (the `]]>` count), `XmlObjectConverter<T>.Write` (reference handling), and type-info creation (one `[XmlRoot]` lookup per type). The ratios in [PR plan](22-pr-plan.md) and [optimization](23-optimization.md) are from before this slice.

The Native AOT smoke (`XmlAotPublishTests`, on the net11.0 test host) publishes and runs `CloudNimble.XmlEssentials.Tests.Aot` and passed with these changes. No benchmark was run.

## Slice 2 decisions

Recorded as each fix lands. The BCL facts were taken from a probe of .NET 11, not from memory.

1. **`CurrentDepth` is the number of elements a token is inside** ([reader](04-api-reader.md)). The root start tag is 0, an empty element and a start tag in the same place agree, and a start tag and its end tag agree. This is what `XmlReader.Depth` and `Utf8JsonReader.CurrentDepth` report. It replaces "the number of elements open after the token", which put a start tag one deeper than an empty element beside it. After a `Read` that returns `false` for want of input the reader is between tokens, and the depth is the number of open elements. Every caller that prints or compares depths sees new numbers for start tags of elements with content.
2. **`Skip` and `TrySkip` do nothing on a token that is not a start tag**, as `Utf8JsonReader.Skip` does on a value.
3. **`WriteRawValue` validates by default** ([writer](05-api-writer.md)). `skipInputValidation` turns the check off. The input is read inside the smallest document that puts it in the same place: the open element with the namespaces in scope, an attribute, or the document level, where it may hold the one root element. An attribute value may not contain a quotation mark or `<`. `XmlWriterOptions.SkipValidation` also turns the check off. A raw value in an attribute used to close the start tag first, which broke the attribute; that is fixed.
4. **Indentation covers comments and processing instructions.** Each gets its own line unless the element it is in holds text, as `System.Xml.XmlWriter` writes them.
5. **`Dispose` flushes before it reports unclosed elements.** `Utf8JsonWriter` does not throw at all; the check stays, because a document cut short should not look complete.
6. **The indent character is a space or a tab**, as in `System.Text.Json`. A non-ASCII character was cut down to one byte. The null character of `default(XmlWriterOptions)` still means a space.
7. **A negative limit is an `ArgumentOutOfRangeException` when it is set** (part of F40), on `XmlReaderOptions`, `XmlDocumentOptions`, `XmlWriterOptions` and `XmlSerializerOptions`. 0 still means the default.
8. **The declared encoding is checked for bytes only** ([XML fidelity](02-xml-fidelity.md)). A string or a span of characters has no encoding left to declare, so `XmlSerializer.Deserialize`, `XmlDocument.Parse` and `XmlNode.Parse` read a string whose declaration says `utf-16`, as `System.Xml` does. UTF-8 bytes with that declaration are still rejected.
9. **UTF-16 and UTF-32 bytes are named as such**: "XmlEssentials is UTF-8 only. The input is UTF-16 or UTF-32.", from the first two bytes, with or without a byte order mark.
10. **Half a surrogate pair is an error, not U+FFFD**, wherever the writer takes characters. This reverses what slice 1 pinned for segments (which then matched a single call); the two still agree. `System.Xml.XmlWriter` throws too.
11. **`1e400` still reads as infinity.** That is what the BCL does; it is pinned and documented, not changed.
12. **`XmlDocument.WriteTo` writes the declaration the document has, whatever `OmitXmlDeclaration` says.** The finding called this a defect. It is the design: the declaration is content of the parsed document, the option only decides whether the writer adds one to a document that has none, and writing with it set is how a parsed document is written back as it was ([DOM](06-api-dom.md), [XML fidelity](02-xml-fidelity.md)). `XmlDeclarationNode.WriteTo` now follows the same rule and records its declaration with the writer, so a writer that adds declarations no longer writes a second one.
13. **Name lookups given no namespace match any namespace** ([DOM](06-api-dom.md) says so). That stays, and is pinned. `XmlElementNode.SetAttribute(name, value)` is different: to set is to name exactly, so it sets the attribute in no namespace and no longer overwrites one in another namespace.
14. **An element's `Children` take only content.** An attribute or a declaration added there is an `XmlException`. An index assignment that is refused leaves the old node in place, in both node lists.
15. **`XmlNode.ToString()` writes by the rules of XML 1.1**, because a node does not know its version. A tree parsed from XML 1.1 can be written, and NEL and LS in text are written as references.
16. **`XmlNode.Parse` and `XmlNode.ParseValue` return `XmlNode`, not `XmlNode?`** (public signature). `XmlDocument.ParseValue` throws when the reader has no element left.
17. **`SerializeToElement` returns an element whose document holds no pooled memory** (it copies out of the pools and returns the rented arrays). That settles the open question; the cost is one more copy than `SerializeToDocument`.
18. **A stack is read back with the same top.** It is written from the top down, as it enumerates, and the items are pushed in reverse when it is read. System.Text.Json turns a stack over on every round trip. The same holds for `ConcurrentStack<T>` and `ImmutableStack<T>`.
19. **A collection or dictionary that can be written and not created fails when it is read**, with `NotSupportedException` and a message that says what the type needs. `ReadOnlyCollection<T>`, which System.Text.Json refuses, is supported, because it has a constructor that takes the items.
20. **A null dictionary value is an entry marked `xsi:nil`** ([object mapping](09-object-mapping.md)), under every ignore condition. An empty element reads as an empty value, never as null.
21. **`IReadOnlyDictionary<,>` and `IImmutableDictionary<,>` are dictionaries**, written as `Dictionary<,>` is.
22. **A collection with no setter is filled** (replaced by decision 46: only when it is populated). `System.Xml.Serialization` does this; System.Text.Json does it only under `JsonObjectCreationHandling.Populate`. The items are added to what the collection holds, so a list a constructor seeds with one item holds that item and the ones read. There is no option for it.
23. **A null wrapped collection and a wrapper marked `xsi:nil` are the same thing in both directions.**
24. **`DefaultIgnoreCondition = Always` throws `ArgumentException`**, as it does in System.Text.Json. In a generated context the attribute's value reaches the same setter, so it fails when the context is created.
25. **An unknown discriminator falls back to the declared type on read**, for both fall-back settings. System.Text.Json throws for every setting. Reading the declared type means a document that names a derived type this build does not know is still readable.
26. **XML values (`XmlElement`, `XmlDocument`, `XmlNode`, `XmlElementNode`) are the document when they are the root, and one element inside the member's element when they are a member.** This is what `System.Xml.Serialization` writes. Only an element can be the value; a text node is refused when it is written, because it would not read back. An `XmlDocument` is written as its document element: its declaration and anything outside the root are not written. A null root is an element marked `xsi:nil`, and that reads back as null for the reference types.
27. **A value declared as `object` is written as the type it has and read as an `XmlElement`.** A document does not record the type, and `xsi:type` is not written. `new object()` is an empty element. As the root, the element is named after the value's type, so `Deserialize<object>` accepts any document element. There is no option for it.
28. **Every anonymous type is named `AnonymousType`.**
29. **`PropertyNameCaseInsensitive` applies to the document element**, and ignoring case is an ASCII rule: a name with characters outside ASCII matches only itself.
30. **A converter named on a member is honored by the reflection resolver** (`[XmlConverter]` on a property or field). It reads and writes the whole value: the member may be an attribute or text, a collection is not taken apart, and a converter for `T` serves a member of type `T?`. A generated context honors it too (decision 50).
31. **Replaced by decision 50.** It read: a generated converter either follows an option or refuses it. It reads `DefaultIgnoreCondition`, `PropertyNameCaseInsensitive`, `NumberHandling`, `RespectNullableAnnotations` and `RespectRequiredConstructorParameters` from the options when it runs. The naming policies, `DefaultPropertyMapping`, `IncludeFields` and the two ignore-read-only switches are compiled in from `[XmlSourceGenerationOptions]`; options that ask for anything else, or that supply a converter for a type the generated code writes itself, get `NotSupportedException` when the type info is first created. Public API added for generated code: ten members on `XmlMetadataServices` (`GetBuiltInTypeInfo`, `CreateCollection`, `AddItems`, `VerifyGeneratedOptions`, `WriteCData`, `CreateCollectionInfo`, `CreateArrayInfo`, `CreateDictionaryInfo`, `CreateEnumInfo`, `CreateNullableInfo`) and four parsers on `XmlLexical` (`TryParseInt128`, `TryParseUInt128`, `TryParseBigInteger`, `TryParseHalf`).
32. **A generated context answers for what it lists, what it reaches, and types whose converter exists already.** Those last are the built-in scalars and their nullable forms, the XML values, `object`, and a type the caller supplied a converter for. For anything else `GetTypeInfo` returns null: a class, struct or record, and also an enumeration, a collection, a dictionary, or the nullable form of a struct that no listed type uses. A context never maps members through reflection and never closes a generic type at run time. List a collection type on the context when it is the value that is serialized. The type is the type argument of `[XmlSerializable<T>]`, so an array or any other closed type can be listed; the attribute has no form that takes `typeof`.
33. **The attribute enumerations of `[XmlSourceGenerationOptions]` are read.** `DefaultIgnoreCondition` and `DefaultPropertyMapping` are bytes, and the generator reads any integral value. They seed the context's options.
34. **In an asynchronous sequence the values of one document share one set of references**; each top-level value has its own.
35. **A generated context creates collections, dictionaries, enumerations and nullable values with every type argument named.** The walker lists each such type it reaches, and the context creates it through `XmlMetadataServices.CreateCollectionInfo`, `CreateArrayInfo`, `CreateDictionaryInfo`, `CreateEnumInfo` or `CreateNullableInfo`. Native AOT cannot close a generic type over a value type at run time, and the publish test caught exactly that for a dictionary member. `XmlAotPublishTests` publishes and runs a type with a dictionary, a queue, a set, an immutable array, an array, a collection with no setter, an `XmlElement` and an `object` member, with reflection off.
36. **A generated context writes a dictionary member as a dictionary**, as the reflection resolver does.
37. **A constructor whose parameter belongs to an ignored member can be chosen.** The public constructor with the most bindable parameters wins, and the ignored parameter is passed the default of its type.
38. **A context asked by other options answers for those options.** A generated context implements the resolver interface itself: asked by options that are not its own, it creates type info for them, for every type it lists or reaches. A hand-written context goes through `XmlSerializerContext`, which answers for a built-in scalar, an XML value, or `object` with the options that ask, and calls `GetTypeInfo(Type)` for anything else.
39. **Members of a generated converter keep their declaration order however many there are.** The walker sorts stably, as the reflection resolver does; `List<T>.Sort` is not stable and reorders ties in a type with more than sixteen members.
40. **A listed type that an earlier listed type reaches still gets its property on the context**, and a type with `[XmlConverter]` is the runtime library's even when it is an enumeration. A listed enumeration honors a converter in `options.Converters`.
41. **An unmapped member is skipped or refused the same way by both resolvers**, mixed content and a text member that is not a single value are compile-time errors in a generated context (XMLESS014, XMLESS015), and a number is read by the same converter in both, so an empty element is rejected by both.
42. **A type in a generated context is named after itself and its type arguments**, and no two types share a name: `Pair<int>` is `PairInt32`, an array of `Order` is `OrderArray`, and a second type that would repeat a name gets a number. A root keeps the name it is listed under.
43. **An attribute that names a type takes it as a type argument, and has no form that takes `typeof`** ([K50](01-identity-and-decisions.md#key-decisions)). `[XmlSerializable<Order>]` and `[XmlConverter<MoneyConverter>]` replace `[XmlSerializable(typeof(Order))]` and `[XmlConverter(typeof(MoneyConverter))]`. `XmlDerivedTypeAttribute<T>`, `XmlElementAttribute<T>` and `XmlArrayItemAttribute<T>` were already the only way to give those attributes a type. The compiler checks the type: a converter must derive from `XmlConverter` and have a public parameterless constructor, and it is created with `new`, not through reflection. An unbound generic type is a compiler error (CS7003); the generator reports XMLESS002 for it as well and generates nothing.
44. **Null is written as `xsi:nil`, and `DefaultIgnoreCondition` is the one option about nulls** ([K49](01-identity-and-decisions.md#key-decisions)) ([object mapping](09-object-mapping.md#null-empty-and-nillable)). `xsi:nil` is how XML spells `null`, so `XmlNilHandling` and `NilHandling` do not exist, on the options or on `[XmlSourceGenerationOptions]`. `DefaultIgnoreCondition` and `[XmlIgnore(Condition = …)]` map one to one onto `JsonIgnoreCondition`: `Never` writes a null member as `xsi:nil`, `WhenWritingNull` and `WhenWritingDefault` leave it out. As in System.Text.Json the condition is about members only: a null collection item, a null dictionary value and a null root are always written. A null is never written as an empty element, which read back as an empty string or not at all.
45. **`RespectNullableAnnotations` does what it does in System.Text.Json** ([object mapping](09-object-mapping.md#null-empty-and-nillable)). It was stored and never read. Its rules were taken from a probe of .NET 11 and are listed in the object mapping spec. The `Strict` preset turns it on, as `JsonSerializerOptions.Strict` does. Generated converters follow it, and `[XmlSourceGenerationOptions(RespectNullableAnnotations = true)]` seeds it. Tests: `XmlSerializerNullableAnnotationTests`, and `NullableAnnotations_AreRespectedAsTheReflectionResolverRespectsThem` in `XmlSerializerGeneratedOptionsTests`, which runs every case through a generated context and the reflection resolver and requires the same result.
46. **`PreferredObjectCreationHandling` and `[XmlObjectCreationHandling]` do what they do in System.Text.Json** ([K51](01-identity-and-decisions.md#key-decisions)) ([object mapping](09-object-mapping.md#object-creation-handling)). The default is `Replace`, so a member with no setter is not read; decision 22 filled a collection with no setter always, and that now happens under `Populate`. `Populate` adds to collections and dictionaries and sets the members of an object that exists, and the attribute on a member that cannot be populated is refused, with the messages of System.Text.Json. Generated converters follow it for collections and dictionaries and refuse it for objects (XMLESS016, and `NotSupportedException` under the option). Public API added: `XmlObjectCreationHandling`, `XmlObjectCreationHandlingAttribute`, the option (also on `[XmlSourceGenerationOptions]`, as System.Text.Json has it), `XmlMetadataServices.AddEntries`, and a member name on `XmlMetadataServices.AddItems`. Tests: `XmlSerializerObjectCreationTests`, `XmlSerializerGetterOnlyCollectionTests`, `ObjectCreationHandling_*` in `XmlSerializerGeneratedParityTests`, and `XmlSerializerInternalsTests`.
47. **`XmlIgnoreCondition` has `WhenWriting` and `WhenReading`, with the values and meaning of `JsonIgnoreCondition`** ([object mapping](09-object-mapping.md#null-empty-and-nillable)). A member that takes nothing from the document (never read, or no setter and not populated) has its element passed over without being read, as System.Text.Json skips it; it used to be parsed and dropped, so content that was not a value of the member's type threw. Generated converters follow both, and report a required member that is never read as XMLESS017. As the default for every member (`DefaultIgnoreCondition`), `WhenWriting` and `WhenReading` are accepted and have no effect, which is what System.Text.Json does with them. Tests: `XmlSerializerIgnoreDirectionTests`, and `IgnoreConditions_ForOneDirection_*` and `IgnoreConditions_WhenReadingOnARequiredMember_IsReported` in `XmlSerializerGeneratedOptionsTests`.
48. **`UnknownTypeHandling` is the counterpart of the System.Text.Json option** ([object mapping](09-object-mapping.md#built-in-primitives-serializer)). `XmlUnknownTypeHandling.XmlElement` (default) reads a value declared as `object` as an `XmlElement`, as System.Text.Json reads a `JsonElement`; `XmlNode` reads an `XmlNode` that can be changed, the counterpart of `JsonNode`. It applies to members, list items, dictionary values and the root, in the reflection resolver and in generated contexts, and `[XmlSourceGenerationOptions]` carries it. Tests: `XmlSerializerUnknownTypeTests`, and `UnknownTypeHandling_IsFollowed` in `XmlSerializerGeneratedOptionsTests`.
49. **`AllowOutOfOrderMetadataProperties` does not exist, because the question it answers cannot arise in XML** ([K48](01-identity-and-decisions.md#key-decisions)). In JSON the metadata (`$id`, `$ref`, `$type`) are properties, and properties have an order. Here a reference id, a reference and a discriminator are attributes or the element name, and XML 1.0 section 3.1 says the order of attributes is not significant. They are accepted in any position, which `MetadataAttributes_AreAcceptedInAnyPosition` in `XmlSerializerMemberRulesTests` pins. An option that rejected one order would contradict the specification.
50. **Source generation emits metadata, and one engine reads and writes** ([K52](01-identity-and-decisions.md#key-decisions), [source generation](10-source-generation.md), [single engine](25-single-engine-metadata.md)). The generator wrote a converter per type, so the library had two engines and every difference between them was a refusal or a diagnostic. It now writes what System.Text.Json's generator writes: an `XmlObjectInfoValues<T>` per object type, and in `Default` and `Serialization` mode a write fast path as its `SerializeHandler`. The reflection resolver's binder reads from member facts that reflection or generated code fills. A generated context gives the reflection resolver's result for every option and feature; `Serialization` alone writes with the options it was compiled for and throws `InvalidOperationException` otherwise; the mode on `[XmlSerializable<T>]` is honored; every mode is Native AOT-safe. Retired: XMLESS008, XMLESS009, XMLESS014, XMLESS016, the `NotSupportedException` refusals, `XmlMetadataServices.VerifyGeneratedOptions`, `Read`, `ReadAttribute`, `AddItems`, `AddEntries`, `CreateCollection`, `RejectUnmappedAttribute`, `RejectUnmappedElement`, the generated read code, and `XmlCollectionFactory<,>`. A converter the caller supplies for a type takes the place of its generated metadata, as in System.Text.Json. A constructor marked `[XmlConstructor]` that is not public is called through an accessor, where XMLESS002 refused it.
51. **Members of the same name follow System.Text.Json** ([K53](01-identity-and-decisions.md#key-decisions), [object mapping](09-object-mapping.md#members-of-the-same-name)). The reflection resolver took `[XmlIgnore]` from the property an override overrides and nothing else, generated metadata took nothing, and both threw for a plain override, because the base property and the override were two members with one name. The rules were taken from a probe of .NET: a member is governed by its own attributes; an override or a `new` member takes the place of the base member; an ignored override hides the property it overrides; an ignored `new` member does not; unrelated members with one XML name are an error. Decided by the owner: match System.Text.Json on both.
52. **`XmlMetadataServices.CreateEnumConverter<T>` is removed** (2026-11-24, at the owner's direction; part of D1). Nothing called it: the generator never emitted a call, and an enumeration gets its built-in converter through `XmlSerializerOptions.GetTypeInfo<T>()` or a context's `XmlTypeInfo<T>` property. Its one test, `XmlMetadataServices_CreateEnumConverter_RoundTripsAName` in `XmlSerializerGeneratorTests`, was removed in the same change, which the owner directed.
53. **An XML value in a slot declared as `object` fills the element that names it** (N5, [object mapping](09-object-mapping.md#built-in-primitives-serializer)). Decision 48 reads the member's, the item's or the entry's own element as the value, and the write put the whole element inside that element again, so a read and a write nested it. The read stays, because the content of such an element may be text, which no inner element can hold. The write changed: an `XmlElement` or an `XmlElementNode` is written as its attributes and its children, under the name of the member, the item or the entry, as every other value is written as its content and not under the name of its type. A prefix declaration on the element is written; a default namespace declaration is not, because the element it would apply to is named already. The root, and a member declared as `XmlElement` or `XmlNode`, are unchanged. Tests: `ReadValues_AreWrittenBackAsTheyWereRead` and `Element_InAnObjectMember_TakesTheNameOfTheMember` in `XmlSerializerUnknownTypeTests`.

Decided by the owner on 2026-11-24: a document that is read, changed and written back keeps its flow, and anything that is rewritten is rewritten by a setting the caller controls, the same way everywhere. Added: `XmlEmptyElementStyle` (`SelfClosing`, `SelfClosingWithSpace`, `StartAndEndTag`) and `XmlAttributeStyle` (`Inline`, `PerLine`, with `AttributesPerLine`) on `XmlWriterOptions` and `XmlSerializerOptions`; `XmlElementNode.IsEmptyElement`. The default stays `Environment.NewLine`, so on Windows a document read with LF is written with CR LF unless `NewLine` is set; `XmlElement.GetRawXml()` and `XmlNode.ToString()` take no options and give LF. `OmitXmlDeclaration` is the setting for the declaration: `System.Xml` adds one on save too (probed). It is not kept and there is no setting for it. `XmlDocument.WriteTo` drops it, and `XmlNode.Parse` returns the root element, so nothing outside the root is part of the mutable tree. Tests: `XmlWriterStyleTests`.
55. **`XmlSourceGenerationOptionsAttribute.UseStringEnumConverter` is removed** (2026-11-24, at the owner's direction; part of D1). It said what `EnumHandling` says, and the generator read neither. `EnumHandling` stays as the one setting. The property's three lines in `XmlSourceGenerationOptionsAttribute_KeepsEveryValueItIsGivenAndStartsUnset` (`XmlSerializerGeneratorTests`) went with it; the test stays.
56. **`XmlRootAttribute.IsNullable`, `XmlArrayAttribute.IsNullable` and `XmlValueKind.Document` are removed** (2026-11-24, at the owner's direction; part of D1). Nothing read the two properties: a null root is always the document element marked `xsi:nil`, and a null wrapped collection is always the wrapper marked `xsi:nil`. `XmlElementAttribute.IsNullable` stays, because it is read. No document or node reported `XmlValueKind.Document`; the other values keep their numbers. No test was removed: `TokenType_UnknownKind_IsNone` in `XmlDocumentInternalsTests` used `Document` as its unknown kind and now uses the value 1, which the enumeration no longer names.
57. **Seven options of `[XmlSourceGenerationOptions]` and two namespaces are implemented** (2026-11-24, at the owner's direction; part of D1). *The options.* `EmitByteOrderMark`, `EnumHandling`, `IgnoreReadOnlyFields`, `IgnoreReadOnlyProperties`, `MaxDepth`, `PropertyNameCaseInsensitive` and `XmlVersion` are copied to the options of the context's `Default`, as the other properties are. With `IgnoreReadOnlyFields` or `IgnoreReadOnlyProperties` the write fast path is not used, which `XmlMetadataServices.CanUseSerializeHandler` already decided. `DiscriminatorPlacement` is not among them: `XmlSerializerOptions` has no such property. *`XmlArrayItemAttribute.Namespace`* is the namespace of the items of a collection in a wrapper, with the meaning `System.Xml.Serialization` gives it (probed): null writes the item under its name alone, so it is in the wrapper's namespace when the wrapper has one; a namespace is declared on the item; an empty string writes `xmlns=""`. With no wrapper the item is the member's element, and the property names nothing. Reading is unchanged: every element in a wrapper is an item. A type with such a member has no write fast path. *`XmlDerivedTypeAttribute.Namespace`* is the namespace of the element named for the derived type, with the same three meanings. A derived type that has one is matched on its namespace as well as its local name when it is read, so two derived types can share a local name. With `Attribute` or `XsiType` placement there is no such element, and a namespace that is not null is `NotSupportedException` when the type is bound. Tests: `XmlSerializerElementNamespaceTests`; `EverySeed_ReachesTheOptionsOfTheDefaultContext` and `ElementNamespaces_AreFollowedByAGeneratedContext` in `XmlSerializerGeneratedOptionsTests`.

The generator never read it and `XmlSerializerOptions` has no property to copy it to. Where a discriminator is written is a choice for each type, made with `[XmlPolymorphic]`; System.Text.Json has no setting for all types either. The property's two lines in `XmlSourceGenerationOptionsAttribute_KeepsEveryValueItIsGivenAndStartsUnset` (`XmlSerializerGeneratorTests`) went with it; the test stays.

They were always `false` and empty, and were there only to mirror `Utf8JsonReader`: a multi-segment sequence is copied into one buffer before it is read, so a value is always in `ValueSpan`. No test was removed: three assertions on the two members went from two tests in `Utf8XmlReaderTests`, and one line from sample 22 and its pinned output.

It is the System.Text.Json feature of .NET 11: the derived types of a closed type (a class declared `closed`, C# 15) are taken from the list the compiler writes into `IsClosedTypeAttribute`. The rules were taken from a probe of .NET 11 and are listed under object mapping. The inference is compiled for `net11.0` only, as the owner asked; in the `net10.0` build no type is closed. The attribute's value is unset until it is set, as in System.Text.Json, so that the option can decide. Tests: `XmlSerializerClosedTypeTests`; `ClosedTypes_AreInferredByAGeneratedContext` in `XmlSerializerGeneratedOptionsTests`; sample 16 `InferClosedTypes`.
61. **The serializer sets `XmlException.Path`** (2026-11-24, at the owner's direction; row 13 of the [PR plan](22-pr-plan.md)). It is the counterpart of `JsonException.Path`, whose behavior was taken from a probe of .NET: a path with the names and the positions on the way to the error when a document is read, a path of names with no positions when an object is written, a path on an exception a converter throws with its message left alone, and the path and the line added to the messages the library makes. *The form* is XPath's, because the path is into an XML document: `/Order/Lines/Line[1]/@sku`. Each element from the document element down; `@name` for an attribute; `text()` for the text of an element; the position of an item of a collection after its name, counted from 0, as System.Text.Json counts; an entry of a dictionary by the element named for its key; an item of a derived type by the name its element has in the document. *On read* each level adds its segment as the exception passes through it: the member loops of the object converter, the loops over the items of a collection and the entries of a dictionary, a derived type, and the document element. The position (`BytePosition`, `LineNumber`, `LinePosition`) is filled in from the reader for an exception that has none, which is every exception for a value that cannot be converted. *On write* the path is the elements the writer has open, which is the one thing the engine and a generated write fast path share. An element written whole, with no frame of its own, is not in it, so the path of a text value or an attribute value that the writer refuses ends at the element that holds it. *The message* (at the owner's direction: "It should count the same as STJ. The Message should match STJ."). `XmlException.Message` is overridden. For an exception the library creates that has a path it ends as System.Text.Json's does: ` Path: /Order/@Id | LineNumber: 1 | BytePositionInLine: 16.`, or ` Path: /Order/Lines.` when no line is known, which is every write. The line and the position are the values of `LineNumber` and `LinePosition`. The library creates its exceptions with the internal `XmlException.Create`; an exception made with a public constructor, which is what a converter throws, keeps its message. Generated code creates its exceptions with `XmlMetadataServices.CreateException`, so a write fast path and the engine report the same message. An exception from the reader, a document or a node used without the serializer has no path, so its message is as it was. *Not changed:* `NotSupportedException` and `InvalidOperationException`, which have no path; and an exception from the reader, a document or a node used without the serializer. A path given to the public constructor is left as it is. Tests: `XmlSerializerExceptionPathTests`; `ExceptionPaths_AreTheSameFromAGeneratedContext` in `XmlSerializerGeneratedOptionsTests`; sample 7 `LocateError`.
62. **Three System.Text.Json parity gaps are closed** (2026-11-24, at the owner's direction; part of D6). The member lists were taken from a probe of .NET 11, not from memory. *The writer.* `Utf8JsonWriter.WriteString` and `WriteNumber` take a property name as `string`, `ReadOnlySpan<char>`, `ReadOnlySpan<byte>` and `JsonEncodedText`, and `WriteString` takes its value as `string`, `ReadOnlySpan<char>`, `ReadOnlySpan<byte>`, `DateTime`, `DateTimeOffset` and `Guid`. `WriteElementString` and `WriteElementNumber` now take every one of those pairs, with `XmlEncodedText` for the name; `WriteElementBoolean`, `WriteElementBase64String` and `WriteNilElement` gained the `XmlEncodedText` name they lacked. A value as `XmlEncodedText` is not offered: here it is a name, which is never escaped. Every form of a name writes the same bytes. 63. **Two element members may share a local name when their namespaces differ** (2026-11-24). The owner asked for a test that reads and writes a real podcast feed; the serializer refused the type, because RSS has `link`, `title`, `image`, `episode` and `season` beside `atom:link`, `itunes:title`, `itunes:image`, `podcast:episode` and `podcast:season`, and a name was a local name alone. Tests: the four `ElementNamesIn...` tests in `XmlSerializerObjectMappingTests` (both document orders, a third namespace, the same namespace refused, case ignored), `ElementNamesInTwoNamespaces_AreTwoNames_AndEachElementGoesToTheMemberOfItsNamespace` in `XmlSerializerGeneratedParityTests`, and `XmlPodcastFeedTests`. *Left open:* a member with no namespace still takes an element of its local name from a namespace no member names, so a `dc:title` in a feed would be read into `title` ([open questions](20-open-questions.md)). 64. **The serializer writes the prefixes it is given, declared on the document element** (2026-11-24, at the owner's direction; the last item of D6). The owner approved two sources and the names: `XmlSerializerOptions.Namespaces`, and `[XmlNamespaceDeclaration(prefix, namespaceUri)]` on the type, with the options taking precedence. The owner then asked for `XmlDocument.DiscoverNamespaces`, which reads the declarations of an existing document, and for `KnownNamespaces`, a static class of ready-made sets, so that `Namespaces = KnownNamespaces.Podcast` works. *How it works.* The writer already uses a prefix that is in scope, so the serializer only declares: `XmlTypeInfo.WriteStartRoot` at writer depth 0 follows an `XmlDocumentElementPlan` that `XmlNamespaceDeclarations.Plan` makes when the type info is created (options first, in order; then the type's attributes that name neither a prefix nor a namespace already declared). The same method starts the element that holds an asynchronous sequence. The rules are in [object mapping](09-object-mapping.md), "Namespaces on write". *The implementer's choices, not the owner's:* (a) `Namespaces` is `IReadOnlyDictionary<string, string>?`, copied into an ordered read-only dictionary when set, so the order of declarations is the order given and a later change to the caller's dictionary has no effect; (b) a declaration is checked when it is set, by asking a writer, so the rules and messages are the writer's; `ArgumentException` for the options, `InvalidOperationException` when a type with a bad attribute is first used; an empty namespace URI is refused; (c) an empty prefix is the default namespace, because `DiscoverNamespaces` reports one and its result must be assignable; (d) `DiscoverNamespaces` is on `XmlDocument`, beside `Parse`, returns `OrderedDictionary<string, string>`, reads every start tag for prefixes and keeps the first namespace of a prefix, and lists a default namespace only when the document element declares it: a prefix means the same wherever it is declared, but a default namespace from an inner element (XHTML inside a feed) would rename every other element if it were declared for the whole document; (e) the sets of `KnownNamespaces` are in alphabetical order of prefix and leave out a format's own namespace when it is none or is customarily the default (`Edmx` has `edmx` only; the EDM namespace of `Schema` is the default namespace of that element, which is what the writer does unprompted). (f) the declarations are those of the type the document is serialized as, also when the value is of a derived type and the element has the derived type's name; (g) the declaration that names the document element's own namespace is written first, by the writer, whatever its place in the order given. *The URIs of `KnownNamespaces`* were each checked against a primary source on 2026-11-24, character for character: the Podlove Simple Chapters page; the OGC GeoRSS standard; the RSS 1.0 module pages for `slash`, `sy` and `content`; the archived wellformedweb.org page for `wfw`; Google's image, news and video sitemap pages and its play-podcasts schema; the W3C XHTML, SOAP 1.1, SOAP 1.2, SVG, XLink and XML Schema documents; the OASIS OData CSDL XML 4.01 specification; the Dublin Core namespace document; the Media RSS specification; RFC 4287; Apple's podcast requirements; and the Podcast Index namespace document. Eight of them are also in the podcast fixture. The SOAP specifications write their envelope prefix as `SOAP-ENV` (1.1) and `env` (1.2); `soap` is what .NET writes, and is what the sets hold. *A consequence to know:* when the declarations bind the document element's namespace to a prefix and not to the empty prefix, the element is written with the prefix (`<edmx:Edmx>`), no default namespace is in force, and a member with no namespace of its own is written in no namespace instead of inheriting. `XmlSerializer` reads it back all the same; another consumer sees a different name. The namespaces guide warns of it. Tests: `XmlSerializerNamespaceDeclarationTests`; the `DiscoverNamespaces_` tests in `XmlDocumentTests`; `NamespaceDeclarations_OfTheOptionsAndOfTheType_AreWrittenOnTheDocumentElement` in `XmlSerializerGeneratedParityTests`; the Native AOT smoke (`FeatureFeed`); samples 14 `ChoosePrefixes`, `DeclareOnType`, `DiscoverPrefixes` and `UseKnownNamespaces`. With the feed's own prefixes, `XmlPodcastFeedTests` now finds the serializer's output equal to the feed character for character from the first episode to the end, but for quotation marks and apostrophes written as themselves. Not done: `XmlSourceGenerationOptionsAttribute` has no `Namespaces`, because an attribute argument cannot be a dictionary; a generated context takes them from the options it is constructed with, or from the type.

65. **Nine disagreements of D4 are settled in favour of the code** (2026-11-24, at the owner's direction; the spec changed, the code did not). The guides and tests already described the code in every case. (1) A `float` or `double` is written as the shortest text that reads back as the same value, not as `G9` / `G17`; System.Text.Json and `XmlConvert` write the same text (probed on .NET 11: `0.1`, `1E+20`, `1E-07`, `-0`), and [optimization](23-optimization.md) already rules `G17` out. (2) A `DateTimeOffset` always ends with its offset, `+00:00` for zero, and never with `Z`; System.Text.Json does the same, while `XmlConvert` and `System.Xml.Serialization` write `Z` (probed), which the migration guide now says. On read `Z`, `+00:00` and `-00:00` are all a zero offset. (3) `[XmlArrayItem]` without `[XmlArray]` has no effect; `[XmlElement("name")]` renames the repeated element. K8 no longer suggests it adds a wrapper. (4) to (7) `XmlNamespaceAttribute`, `XmlTypeAttribute`, `[XmlNamespaceDeclarations]` and `XmlNamingPolicyAttribute` are removed from the spec: a member's namespace is given on the member, `[XmlRoot]` and `[XmlDerivedType<T>]` name a type, `XmlSerializerOptions.Namespaces` and `XmlDocument.DiscoverNamespaces` replace the declarations member (decision 64), and a naming policy belongs to the options, as in System.Text.Json. (8) `XmlNamespaceDeclaration` is no longer listed as missing. (9) `MaxTextByteCount` counts the bytes of the document, before references and line ends are decoded, which `Text_Limit_CountsTheBytesInTheDocumentNotTheDecodedValue` pins. What D4 still holds is in its row.

66. **An enum member is renamed with `[XmlPropertyName]`, and names are read as System.Text.Json reads them** (2026-11-24, at the owner's direction: "match STJ on case sensitivity; if there is a `JsonSerializerOptions` property for sensitivity, match it"; item 10 of D4). Probed on .NET 11: `JsonSerializerOptions` has no property for enum names (`PropertyNameCaseInsensitive` is the only one with "Case" or "Enum" in its name, and it changes nothing for `JsonStringEnumConverter`); the converter reads the exact name first and then a C# name in any case (`Ab` and `aB` each from their own spelling, `ab` and `AB` as the first); a member renamed with `[JsonStringEnumMemberName]` is read from that name exactly, and no longer from its C# name; of two members with one name the first is read; the property naming policy does not rename enum values. `XmlEnumConverter<T>` now does all of that, with `[XmlPropertyName]` as the attribute, which its usage already allowed on a field. 67. **A token that has not ended is refused once what has arrived is over its limit** (2026-11-24, at the owner's direction; item 13 of D4). `Utf8XmlReader` asked for more data whenever a text node, a CDATA section or a comment ran to the end of a block that was not the last, and checked `MaxTextByteCount` or `MaxCommentByteCount` only when the end of the token arrived. A caller that reads a stream grows its buffer each time it is asked for more, so a sender that never ended the token was buffered without limit; `DeserializeAsyncEnumerable` is such a caller. Every byte from the start of the token's content to the end of the block belongs to the token, so `NeedMoreOf` now throws there when that length is over the limit. CDATA and comments allow two bytes for a terminator the block may have cut. The reader goes back to the start of the token before it throws, so the position in the message is the token's and does not depend on the size of the block. What is **not** changed: the methods that take a whole `Stream` (`Deserialize(Stream)`, `DeserializeAsync(Stream)`, `XmlDocument.Parse(Stream)`, `ParseAsync`, `DiscoverNamespaces(Stream)`) read it to its end before they parse, so nothing but `MaxDocumentByteCount` bounds them while they read. A per-node limit could not protect them anyway: a sender can as well send small nodes without end. The security guide says so. Attribute values got the limit next (decision 68). Tests: `PartialBlock_WithMoreOfATokenThanItsLimitAllows_IsRefusedBeforeTheTokenEnds` and `PartialBlock_WithNoMoreOfATokenThanItsLimitAllows_AsksForMore` in `Utf8XmlReaderResumeTests`; `AsyncEnumerable_ATextNodeThatDoesNotEnd_IsRefusedAtItsLimit_AndTheStreamIsNotReadOn` in `XmlSerializerStreamingTests`, which pins that no read is made after the one that shows the node to be too long. Found on the way: N10.

68. **`MaxTextByteCount` also limits an attribute value and the data of a processing instruction** (2026-11-24, at the owner's direction: "use the same value for now, we can always add a new value in a point release if a split is necessary"; item 12 of D4). Both were unbounded but for `MaxDocumentByteCount`, which is off by default, so the "text bomb" guard of [security](18-security.md) could be walked around with one attribute. Each attribute value is counted on its own, in the bytes of the document, as a text node is, and a namespace declaration is an attribute like any other. 70. **Type names are the ones `System.Xml.Serialization` writes** (2026-11-24, at the owner's direction; item 11 of D4, and it replaces the rule of K25). The implementer first proposed only one name for every sequence and called the scalar names "settled"; the owner rejected that: nothing is settled before the library ships, and the right naming should be chosen on its merits. K25's `Int32` had no recorded reason. Probed on .NET 11, `XmlSerializer` names a built-in type by its XML Schema type (`int`, `string`, `boolean`, `dateTime`, `unsignedInt`, `base64Binary`; and `guid`, `dateOnly`, `timeOnly`, `dateTimeOffset`, `char` where the schema has no name), every sequence `ArrayOf` + the item name with a capital (`ArrayOfInt` for `int[]`, `List<int>`, `HashSet<int>` and a class derived from `List<int>`; `ArrayOfArrayOfInt`; `ArrayOfTypename` for an item named `type-name`), and a generic class by its CLR name + `Of` + the CLR names of its arguments (`BoxOfInt32`, `BoxOfListOfInt32`, `BoxOfArrayOfByte`, `BoxOfNullableOfInt32`). `XmlTypeNames` now gives exactly those names, and they are used for a document element, for the items of a wrapped collection, and for the element that holds an asynchronous sequence, which therefore has the name a `List<T>` has. The rules are in [object mapping](09-object-mapping.md). *What it buys:* XML Schema names are XML's own vocabulary for these types; a value or a collection that the old serializer wrote as a document is read as it is, and the reverse; `Deserialize<List<T>>`, `Deserialize<T[]>` and `DeserializeAsyncEnumerable<T>` read each other's documents, which they could not. *The owner's choice:* `[XmlRoot("x")]` names the type inside collections too, where the BCL uses `[XmlType]`. *The implementer's:* types the BCL cannot serialize keep CLR-style names (`DictionaryOfStringInt32`, `Int128`, `Half`, `BigInteger`, `ReadOnlyMemoryOfByte`); a dictionary of a nullable value or of `byte[]` is now `DictionaryOfStringNullableOfInt32` and `DictionaryOfStringArrayOfByte`, which is how the BCL spells those arguments in a generic name. *What changed for a caller:* every root name of a built-in type and of a collection, and the default item name of a wrapped collection; a class that derives from a collection no longer has its own name at the root (`ArrayOfInt`, not `FixedSizeBag`), as in the BCL. The generator's fast path took the item name of a wrapped collection from the symbol's own name; it now uses the same rules (`XmlTypeNameSymbols`). Tests: about 1,000 expected strings across the serializer tests and samples were renamed, by a script that touched only XML tags and paths inside string literals, and the rest by hand; `DocumentElement_IsNamedAsXmlSerializerNamesTheType` pins the table, `Collections_OfOneItemType_WriteTheSameDocument_AndReadEachOthers` and `TypeNamedByXmlRoot_HasThatName_AsAnItemOfACollection` the two rules about collections, and `ItemsOfAWrappedCollection_AreNamedForTheirType_AsTheReflectionResolverNamesThem` that a generated context writes the same item names.

### Hot paths changed

No benchmark was run in this slice, as asked. These paths changed and their rows in [PR plan](22-pr-plan.md) and [optimization](23-optimization.md) are from before the change:

- **Reader**: `Read` clears one more flag (`CurrentDepth`), and the first read of a document looks at up to four bytes for a UTF-16 or UTF-32 signature.
- **Writer**: `WriteRawValue` now checks its input unless told not to; `WriteStringValue` from characters uses a strict transcode that rejects half a surrogate pair; comments and processing instructions are indented.
- **Serializer, reflection**: a member written tests its ignore condition once more (`WhenWriting`), and a member read tests one flag before anything else (never stored); a member read or written tests one more field for null (the nullable-annotation refusal); a member that is not a built-in scalar tests one flag when it is read (populate), and an object is read through one more call (`ReadInto`); a member name is compared exactly and then, only when names are matched without case, a second time; the document element check goes through the same comparison; a dictionary entry tests its value for null before it is written; a wrapped collection tests its wrapper for `xsi:nil`.
- **Serializer, generated** (decision 50): reading goes through the engine, from generated metadata, where a generated converter read with code of its own. Writing uses the fast path when the options allow it and the engine otherwise. The source-gen rows in [benchmarks](15-benchmarks.md) are from before this change. No benchmark was run; the owner asked that optimization and benchmarks wait for the end of the work.
- **Serializer, reflection** (decision 51): binding a type takes its members in three passes where it took one. This is paid once for each type and options instance.
- **Serializer** (decision 61): the loops that read the attributes and the child elements of an object, the items of a collection in a wrapper or at the root, and the entries of a dictionary each run inside a `try` with a `catch` that adds to the path. Reading the document element and writing it do too. Nothing is done unless an `XmlException` is thrown.
- **Writer** (decision 54): the set of characters that text is copied verbatim under is a field of the writer where it was a static, chosen from `NewLine`; with CR LF, text that holds a line break takes the escaping path. `WriteStartAttributeTrusted` tests one field before it writes a pre-encoded attribute head, `WriteTagOpen` tests the same field, and each time the buffer is handed on one call returns at once unless `AttributeStyle` is `PerLine`. With `PerLine`, the output is scanned once for the white space that starts each line.

71. **`XmlSerializerOptions.Bcl`, and the settings it is made of** (2026-11-24, at the owner's direction). A fourth preset, `XmlSerializerDefaults.Bcl`, writes what `System.Xml.Serialization.XmlSerializer` writes for the same type. Every value in it was probed on .NET 11 and `XmlSerializerBclDefaultsTests` compares a whole document with the one that serializer wrote. It needed five settings that did not exist: `DefaultCollectionMapping` (`Wrapped`), `XmlIgnoreCondition.WhenWritingNullReference` (the old serializer leaves a null reference out and writes `xsi:nil` for a nullable value type), `MemberOrder` (`FieldsFirst`), `CharHandling` (`Number`) and `UtcOffsetHandling` (`WriteZ`). The owner proposed a broader `TimeHandling`; the probe showed one difference in all the date and time types, the spelling of a zero offset, so the setting is that and no more. The default stays `+00:00` (decision 65). One rule changed to match System.Text.Json, which the probe also showed: `IgnoreReadOnlyProperties` and `IgnoreReadOnlyFields` no longer leave out a collection or a dictionary, and the guide that said they did is corrected. The generator compiles `DefaultCollectionMapping` into the fast path; the fast path is not used under the other four. Known differences that remain: the declared encoding is always `utf-8`; a derived type is written with `xsi:type` only where `[XmlPolymorphic]` asks; the old serializer skips a getter-only property typed as a collection interface and refuses a property with a non-public setter.

72. **`[XmlMixed]` is for a collection of `XmlMixedContentItem` only, and anything else is refused** (2026-11-24, at the owner's direction; item 15 of D4). The spec named `List<XmlNode>`, `List<object>` and lists of POCOs; the code never read or wrote any of them, and a member of another type was written as nothing. The binder now throws `NotSupportedException` when the type is bound, with the same message through the reflection resolver and a generated context. The spec is corrected.

73. **The XSD generator maps inheritance, optional members and references, and reports what it does not map** (2026-11-24, at the owner's direction; item 17 of D4). Changed: a named complex type is a class named for the type, and a global element of that type names its root (it had a class of its own with the type's members copied in); `xs:extension` and `xs:restriction` of a named complex type are CLR inheritance with `xsi:type` polymorphism declared on every base class (the members were copied into an unrelated class); `minOccurs="0"` and an attribute that is not required give a nullable member; only `nillable="true"` writes `xsi:nil`, and any other null is left out; `ref` takes the type of the global declaration (it was `string`); named groups and attribute groups, nested sequences, named and inline simple types that are not enumerations, wrapper elements (`[XmlArray]`), `abstract`, and `xml:lang` are mapped; an enumeration value that is not an identifier keeps its value through `[XmlPropertyName]`; members are no longer ordered with an unstable sort; a type that is polymorphic, or holds one, or has extension data, has no fast path (the flag was not honoured). Found on the way and fixed in the runtime: `xsi:type` is read as a QName, so `p:Circle` finds `Circle`. Not built, and reported by a diagnostic instead: `xs:choice` as polymorphism and substitution groups (the spec said both were mapped; it is corrected), repeating model groups, mixed content, `default` and `fixed`. New diagnostic XMLESS018 (warning) for what cannot round-trip; XMLESS011 stays information. The rest was built next: decisions 74 and 75.

74. **A member can hold a choice of elements, and can be put in no namespace** (2026-11-24, at the owner's direction). Both were found while mapping XSD and are fixed in the runtime, for reflection and generated contexts alike. (a) K35 promised that several `[XmlElement]` on a member are a per-member choice; the binder used the first and ignored the rest, and several `[XmlArrayItem]` were refused. More than one `[XmlElement<T>]`, or more than one `[XmlArrayItem<T>]` in a wrapper, is now a choice bound as the member's derived types with the element name as the discriminator (`XmlObjectBinder.BindChoices`), with the rules in [object mapping](09-object-mapping.md). (b) `Namespace = ""` on `[XmlElement]` or `[XmlArray]` was the same as naming none, so the element took the default namespace in scope. It now means no namespace: written with `xmlns=""`, and read only from no namespace. A type with either has no write fast path.

75. **The XSD generator maps choices, repeating groups, substitution groups, mixed content, defaults and element form** (2026-11-24, at the owner's direction, after decision 73 left them as diagnostics). A choice, a group that repeats, and a `ref` to the head of a substitution group become one member that holds a choice of elements, a list where it repeats, so the order of the document is kept. `mixed="true"` becomes the attributes and one `[XmlMixed]` member. `default` and `fixed` become property initializers. Element and attribute form are followed, so a schema that does not say `elementFormDefault="qualified"` reads and writes its local elements in no namespace; a global attribute is in the target namespace, which the generator had wrong. Two elements of one CLR type could not share a member then; decision 77 removed that limit.

76. **`XmlPolymorphismOptions` and `XmlDerivedTypeInfo` are out of the spec** (2026-11-24, at the owner's direction; item 16 of D4). The code has neither: `XmlTypeInfo` exposes `Properties` and `CreateObject`, and derived types are declared with attributes. They are a feature to add when someone needs to configure derived types without attributes, not a correction.

77. **A value can name its element, so elements of one type share a member** (2026-11-24, at the owner's direction). A choice member writes a value under the element of its type, which cannot tell two `xs:string` elements apart, so the XSD generator had fallen back to a member per element and lost the order of a repeating group. `XmlNamedValue` (`Name`, `Namespace`, `Value`) is the member's or the item's type in that case: the value names its element, as JAXB's `JAXBElement` does. The runtime binds it in `XmlObjectBinder.BindChoices` and resolves it in `XmlPolymorphism.ResolveWrite`; the rules are in [object mapping](09-object-mapping.md). The generator uses it for a choice, a repeating group and a substitution group whenever two elements have one CLR type, and a repeating group now takes in the elements of the groups nested in it. What is still a member per element: a choice that does not repeat and holds a sequence, a group or a repeating element (nothing is lost, XMLESS011), and a repeating group with `xs:any` or one element name with two types (order lost, XMLESS018).

78. **`Utf8XmlWriter.Reset` discards pending bytes** (2026-11-24, at the owner's direction; D5). It committed them, which put a half-written document into the output when a writer was reset to abandon one. `Utf8JsonWriter.Reset` discards (probed on .NET 11), and so does this now, in all three overloads. A caller that wants the bytes calls `Flush` first; the serializer's own callers already did, or were abandoning the document.

79. **A setter that is not public is not used unless the member is marked `[XmlInclude]`** (2026-11-24, at the owner's direction; D5). The serializer set properties through `private` and `internal` accessors. System.Text.Json does not without `[JsonInclude]` (probed on .NET 11), and `System.Xml.Serialization` refuses such a type. A `set` or `init` accessor is now used when it is public or the member is included; otherwise the property is written and not set, and counts as read-only for `IgnoreReadOnlyProperties`. The reflection resolver (`XmlMemberFacts`) and the generator (`MetadataBuilder`) apply the same rule.
