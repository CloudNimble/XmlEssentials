When a partner gives you an XML Schema (XSD) file, you don't have to write the classes by hand. Add the schema to your project as an `AdditionalFiles` item, and the XmlEssentials source generator writes a class for each element and complex type, an enumeration for each enumerated simple type, and an `XmlSerializerContext` that reads and writes them. This article shows the setup and lists what the generator maps and what it doesn't.

The schema is a build-time input. It isn't loaded, embedded, or checked at run time, so the generated code works in a Native AOT application. XmlEssentials doesn't validate documents against a schema.

## Generate the types

<Steps>
  <Step title="Add the schema file to the project">
    Put the `.xsd` file in your project, for example in a *Schemas* folder. This article uses the following schema:

    ```xml Schemas/catalog.xsd
    <?xml version="1.0" encoding="utf-8"?>
    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema"
               xmlns="urn:example:catalog"
               targetNamespace="urn:example:catalog"
               elementFormDefault="qualified">

      <xs:simpleType name="Availability">
        <xs:restriction base="xs:string">
          <xs:enumeration value="InStock"/>
          <xs:enumeration value="BackOrder"/>
          <xs:enumeration value="Discontinued"/>
        </xs:restriction>
      </xs:simpleType>

      <xs:complexType name="Supplier">
        <xs:annotation>
          <xs:documentation>The company a product is bought from.</xs:documentation>
        </xs:annotation>
        <xs:sequence>
          <xs:element name="Name" type="xs:string"/>
          <xs:element name="Country" type="xs:string"/>
        </xs:sequence>
      </xs:complexType>

      <xs:element name="Catalog">
        <xs:annotation>
          <xs:documentation>The products a shop sells.</xs:documentation>
        </xs:annotation>
        <xs:complexType>
          <xs:sequence>
            <xs:element name="Product" maxOccurs="unbounded">
              <xs:complexType>
                <xs:sequence>
                  <xs:element name="Name" type="xs:string"/>
                  <xs:element name="Price" type="xs:decimal"/>
                  <xs:element name="Availability" type="Availability"/>
                  <xs:element name="Weight" type="xs:double" nillable="true"/>
                  <xs:element name="Supplier" type="Supplier"/>
                </xs:sequence>
                <xs:attribute name="sku" type="xs:string"/>
              </xs:complexType>
            </xs:element>
          </xs:sequence>
          <xs:attribute name="published" type="xs:date"/>
        </xs:complexType>
      </xs:element>

    </xs:schema>
    ```
  </Step>
  <Step title="Declare it as an AdditionalFiles item">
    In the project file, add the schema as an `AdditionalFiles` item. Optionally, set the namespace of the generated code and the name of the generated context:

    ```xml MyApp.csproj
    <ItemGroup>
      <AdditionalFiles Include="Schemas\catalog.xsd">
        <XmlEssentialsNamespace>CloudNimble.XmlEssentials.Samples.Schemas</XmlEssentialsNamespace>
        <XmlEssentialsContext>CatalogXmlContext</XmlEssentialsContext>
      </AdditionalFiles>
    </ItemGroup>
    ```
  </Step>
  <Step title="Build the project">
    Build. The generator adds the classes and the context to the compilation. There are no files to check in.

    ```bash
    dotnet build -c Release
    ```
  </Step>
  <Step title="Use the generated classes and context">
    In your code, create the generated classes as you would your own, and pass the context's type info to `XmlSerializer`:

    ```csharp Program.cs
    var catalog = new Catalog
    {
        published = new DateOnly(2026, 11, 23),
        Product =
        [
            new Catalog_Product
            {
                sku = "KB-01",
                Name = "Keyboard",
                Price = 89.90m,
                Availability = Availability.InStock,
                Weight = 0.8,
                Supplier = new Supplier { Name = "Contoso", Country = "NL" },
            },
            new Catalog_Product
            {
                sku = "MS-02",
                Name = "Mouse",
                Price = 20m,
                Availability = Availability.BackOrder,
                Supplier = new Supplier { Name = "Fabrikam", Country = "DE" },
            },
        ],
    };

    var options = new XmlSerializerOptions
    {
        DefaultNamespace = "urn:example:catalog",
        NewLine = "\n",
        WriteIndented = true,
    };
    var context = new CatalogXmlContext(options);

    string xml = XmlSerializer.Serialize(catalog, context.Catalog);
    output.WriteLine(xml);

    Catalog? copy = XmlSerializer.Deserialize(xml, context.Catalog);
    foreach (Catalog_Product product in copy!.Product!)
    {
        output.WriteLine($"{product.sku}: {product.Name}, {product.Availability}, from {product.Supplier!.Name}");
    }
    ```

    The code produces the following output:

    ```text
    <?xml version="1.0" encoding="utf-8"?>
    <Catalog xmlns="urn:example:catalog" published="2026-11-23">
      <Product sku="KB-01">
        <Name>Keyboard</Name>
        <Price>89.90</Price>
        <Availability>InStock</Availability>
        <Weight>0.8</Weight>
        <Supplier>
          <Name>Contoso</Name>
          <Country>NL</Country>
        </Supplier>
      </Product>
      <Product sku="MS-02">
        <Name>Mouse</Name>
        <Price>20</Price>
        <Availability>BackOrder</Availability>
        <Weight xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:nil="true"/>
        <Supplier>
          <Name>Fabrikam</Name>
          <Country>DE</Country>
        </Supplier>
      </Product>
    </Catalog>
    KB-01: Keyboard, InStock, from Contoso
    MS-02: Mouse, BackOrder, from Fabrikam
    ```
  </Step>
</Steps>

The second product has no weight. Because the schema marks `Weight` as `nillable`, the generated property is `double?`, and a `null` value is written with `xsi:nil="true"`.

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/36_GenerateTypesFromXsd.cs)

## What the generator writes

For the schema above, the generator writes two classes for the `Catalog` element, one class for the `Supplier` type, one enumeration, and one context. Three of them are shown here, without their file headers and namespace:

```csharp Generated code
/// <summary>
/// The products a shop sells.
/// </summary>
[XmlRoot("Catalog", Namespace = "urn:example:catalog")]
public partial class Catalog
{
    [XmlAttribute("published")]
    public global::System.DateOnly published { get; set; }

    public global::System.Collections.Generic.List<global::CloudNimble.XmlEssentials.Samples.Schemas.Catalog_Product>? Product { get; set; }

}

[XmlRoot("Product", Namespace = "urn:example:catalog")]
public partial class Catalog_Product
{
    [XmlAttribute("sku")]
    public string? sku { get; set; }

    public string? Name { get; set; }

    public decimal Price { get; set; }

    public global::CloudNimble.XmlEssentials.Samples.Schemas.Availability Availability { get; set; }

    public double? Weight { get; set; }

    public global::CloudNimble.XmlEssentials.Samples.Schemas.Supplier? Supplier { get; set; }

}

public enum Availability
{
    InStock,
    BackOrder,
    Discontinued,
}
```

What to notice:

- **Names come from the schema unchanged.** The attributes `published` and `sku` become properties with those exact names, lowercase included. A character that isn't valid in a C# identifier becomes an underscore.
- **An anonymous complex type is named after its parent.** The `Product` element inside `Catalog` becomes `Catalog_Product`.
- **Every class is `public partial`.** Add members in a file of your own instead of editing generated code.
- **`xs:documentation` becomes a `<summary>` comment** on the class. Documentation on child elements and attributes isn't copied.

The context is a `public partial class` in the same namespace, with one `XmlTypeInfo<T>` property for each generated class and enumeration: `Catalog`, `Catalog_Product`, `Supplier`, and `Availability`. It has the members every generated context has. See [What the generator adds to your class](/guides/source-generation#what-the-generator-adds-to-your-class).

## Item metadata

| Metadata | Meaning | Default |
| --- | --- | --- |
| `XmlEssentialsNamespace` | The C# namespace of the generated classes and context. | The project's `RootNamespace` followed by `.Generated`. |
| `XmlEssentialsContext` | The name of the generated context class. | The file name in Pascal case followed by `XmlContext`: `CatalogXmlContext` for *catalog.xsd*. |

The generator sees this metadata because the package's build file makes it visible to the compiler. Every file whose name ends in `.xsd` is processed. Other `AdditionalFiles` items, including `.wsdl` files, are ignored.

## The target namespace

The `Default` instance of a generated context has `DefaultNamespace` set to the schema's `targetNamespace`, so documents are written in that namespace with no further setup:

```csharp Program.cs
var supplier = new Supplier { Name = "Contoso", Country = "NL" };

output.WriteLine(CatalogXmlContext.Default.Options.DefaultNamespace);
output.WriteLine(XmlSerializer.Serialize(supplier, CatalogXmlContext.Default.Supplier));
```

The code produces the following output:

```text
urn:example:catalog
<?xml version="1.0" encoding="utf-8"?><Supplier xmlns="urn:example:catalog"><Name>Contoso</Name><Country>NL</Country></Supplier>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/36_GenerateTypesFromXsd.cs)

<Warning>
When you create the context from your own options, as the first example does, set `DefaultNamespace` yourself. Constructor options replace the generated defaults, and without the namespace the document element is written unqualified, which the schema doesn't allow.
</Warning>

When reading, the generated converters match child elements and attributes by local name and don't check their namespace.

## How schema constructs are mapped

### Types

| XSD type | C# type |
| --- | --- |
| `xs:string`, and any type not listed here | `string` |
| `xs:boolean` | `bool` |
| `xs:byte`, `xs:unsignedByte` | `sbyte`, `byte` |
| `xs:short`, `xs:unsignedShort` | `short`, `ushort` |
| `xs:int`, `xs:integer`, `xs:unsignedInt` | `int`, `int`, `uint` |
| `xs:long`, `xs:unsignedLong` | `long`, `ulong` |
| `xs:float`, `xs:double`, `xs:decimal` | `float`, `double`, `decimal` |
| `xs:dateTime` | `DateTime` |
| `xs:date`, `xs:time` | `DateOnly`, `TimeOnly` |
| `xs:duration` | `TimeSpan` |
| `xs:base64Binary` | `byte[]` |
| `xs:anyURI` | `Uri` |
| A named `xs:simpleType` with `xs:enumeration` values | An `enum` with one member for each value |
| A named `xs:complexType` | A class |

<Note>
A named simple type that restricts a base type without enumerations, such as an `xs:int` with a range or an `xs:string` with a pattern, maps to `string`. Types such as `xs:positiveInteger`, `xs:hexBinary`, and `xs:token` map to `string` too.
</Note>

### Structure

| XSD construct | Generated code |
| --- | --- |
| Global `xs:element` with a complex type, inline or by name | A class named after the element, with `[XmlRoot]`. |
| Global `xs:element` with a simple type | Nothing. |
| `xs:sequence`, `xs:all` | One property for each child element. |
| `xs:choice` | One property for each alternative. The choice isn't enforced, and the generator reports `XMLXE011`. |
| `xs:element` with `maxOccurs` greater than 1 or `unbounded` | A `List<T>?` property, written as repeated elements with no wrapper. |
| `xs:element` with `nillable="true"` and a value type | A nullable property, such as `double?`. |
| `xs:element` with an inline `xs:complexType` | A class named *Parent*_*Element*. |
| `xs:attribute` | A property with `[XmlAttribute]`. |
| `xs:simpleContent` with an extension | A `Value` property with `[XmlText]`, and a property for each attribute. |
| `xs:complexContent` with an extension | A class with the base type's members followed by its own. The classes don't inherit from each other. |
| `xs:any`, `xs:anyAttribute` | One `XmlExtensionData? Extra` property with `[XmlExtensionData]`. |
| `xs:annotation` with `xs:documentation` on a global element or a complex type | A `<summary>` comment on the class. |
| `xs:include`, `xs:import` | The generator looks for the other schema by file name among the `.xsd` items of the project, and reports `XMLXE010` when it isn't there. Schemas that span several files aren't covered by a sample in this documentation, so check the generated code when you use them. |

### Not mapped

The generator doesn't act on the following. Where an ID is shown, it reports that diagnostic as information and continues.

| XSD construct | What happens |
| --- | --- |
| `minOccurs`, `use="required"`, `default`, `fixed` | Ignored. No member is marked as required and no default is applied. |
| Facets: `pattern`, `minInclusive`, `maxLength`, and the others except `enumeration` | Ignored. Values aren't validated. |
| An element or attribute declared with `ref` | A `string` member named after the referenced declaration. |
| A model group nested in another, and `xs:group` or `xs:attributeGroup` references | Ignored. |
| `substitutionGroup` on a local element | Ignored (`XMLXE011`). |
| `xs:key`, `xs:keyref`, `xs:unique` | Ignored. `XMLXE011` is reported for those at the top level of the schema or of a complex type. |
| `xs:redefine`, `xs:notation` | Ignored (`XMLXE011`). |
| An enumeration value that isn't a C# identifier, such as `back-order` | The member name has underscores for the invalid characters (`back_order`), and that name is what's written and read. |

<Warning>
Check the last row against your schema. The generated enumeration reads and writes its member names, so a value that had to be changed no longer matches the schema's value.
</Warning>

## Diagnostics

| ID | Severity | When |
| --- | --- | --- |
| `XMLXE010` | Error | The schema contains a DTD or isn't well formed, or an `xs:include` or `xs:import` has no `schemaLocation`, has one with a URI scheme, or names a file that isn't an `.xsd` item of the project. Schemas are never downloaded. |
| `XMLXE011` | Information | The schema uses a construct that's ignored or simplified, as the tables above show. |
| `XMLXE012` | Error | Two components produce the same C# type name. |
| `XMLXE013` | Error | An element or attribute name in the schema isn't a valid XML name. |

## Limits of the generated context

A context generated from a schema is a default-mode context, with the limits those have. In particular, `NilHandling`, `DefaultIgnoreCondition`, and custom converters for class members don't apply. See [Which options generated converters apply](/guides/source-generation#which-options-generated-converters-apply).

To use the generated classes with reflection instead, pass them to an `XmlSerializer` overload that takes options, and pass the options. A call that passes none is redirected to the generated context by an [interceptor](/guides/reflection-vs-source-generation#interceptors).
