## Summary

Options for [XmlSerializer](/api-reference/CloudNimble/Text/Xml/XmlSerializer). Analogous to `JsonSerializerOptions`.

## Usage

`XmlSerializerOptions` holds the settings that control how [`XmlSerializer`](/api-reference/CloudNimble/Text/Xml/XmlSerializer) writes and reads XML: names, indentation, null handling, limits, converters, and where type metadata comes from. It is the counterpart of `JsonSerializerOptions`.

Create an instance once, set its properties in the initializer, and pass the same instance to every call:

```csharp
private static readonly XmlSerializerOptions s_compact = new()
{
    OmitXmlDeclaration = true,
    PropertyNamingPolicy = XmlNamingPolicy.CamelCase,
};
```

```csharp
output.WriteLine(XmlSerializer.Serialize(new InvoiceLine { Sku = "KB-101", Quantity = 2 }, s_compact));
output.WriteLine(XmlSerializer.Serialize(new InvoiceCustomer { Name = "Contoso", Email = "ap@contoso.example" }, s_compact));
```

The code produces the following output:

```xml
<invoiceLine><sku>KB-101</sku><quantity>2</quantity></invoiceLine>
<invoiceCustomer><name>Contoso</name><email>ap@contoso.example</email></invoiceCustomer>
```

There are three ways to get an instance:

- `new XmlSerializerOptions()` for the general defaults, or `new XmlSerializerOptions(XmlSerializerDefaults.Web)` and `new XmlSerializerOptions(XmlSerializerDefaults.Strict)` for the other two sets.
- `new XmlSerializerOptions(existing)` to copy an instance and change the copy.
- The shared, read-only instances `XmlSerializerOptions.Default`, `XmlSerializerOptions.Web`, and `XmlSerializerOptions.Strict`.

An instance becomes read-only the first time it is used, or when you call `MakeReadOnly`. Every option, with its default, is listed in [Configure XmlSerializerOptions](/guides/configure-options).

## Remarks

An instance becomes read-only the first time it is used to serialize or deserialize, or when
[XmlSerializerOptions.MakeReadOnly](/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions#makereadonly) is called. Create one instance and reuse it: the converters and type info it
resolves are cached on the instance.

## Examples

The following examples show the three ways to get an options instance and what happens once an instance is in use.

### Use the built-in instances

```csharp
var line = new InvoiceLine { Sku = "KB-101", Quantity = 2 };

output.WriteLine(XmlSerializer.Serialize(line, XmlSerializerOptions.Default));
output.WriteLine(XmlSerializer.Serialize(line, XmlSerializerOptions.Web));
output.WriteLine(XmlSerializer.Serialize(line, XmlSerializerOptions.Strict));
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?><InvoiceLine><Sku>KB-101</Sku><Quantity>2</Quantity></InvoiceLine>
<invoiceLine><sku>KB-101</sku><quantity>2</quantity></invoiceLine>
<?xml version="1.0" encoding="utf-8"?><InvoiceLine><Sku>KB-101</Sku><Quantity>2</Quantity></InvoiceLine>
```

### Start from a set of defaults and copy an instance

```csharp
var web = new XmlSerializerOptions(XmlSerializerDefaults.Web)
{
    WriteIndented = true,
    NewLine = "\n",
};

var line = new InvoiceLine { Sku = "KB-101", Quantity = 2 };
output.WriteLine(XmlSerializer.Serialize(line, web));

var flat = new XmlSerializerOptions(web) { WriteIndented = false };
output.WriteLine($"Source is read-only: {web.IsReadOnly}. Copy is read-only: {flat.IsReadOnly}.");
output.WriteLine(XmlSerializer.Serialize(line, flat));
```

The code produces the following output:

```text
<invoiceLine>
  <sku>KB-101</sku>
  <quantity>2</quantity>
</invoiceLine>
Source is read-only: True. Copy is read-only: False.
<invoiceLine><sku>KB-101</sku><quantity>2</quantity></invoiceLine>
```

### See when an instance becomes read-only

```csharp
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };
output.WriteLine($"Before first use: {options.IsReadOnly}");

XmlSerializer.Serialize(new InvoiceLine { Sku = "KB-101", Quantity = 2 }, options);
output.WriteLine($"After first use: {options.IsReadOnly}");

try
{
    options.WriteIndented = true;
}
catch (InvalidOperationException ex)
{
    output.WriteLine(ex.Message);
}

var frozen = new XmlSerializerOptions();
frozen.MakeReadOnly();
output.WriteLine($"After MakeReadOnly: {frozen.IsReadOnly}");
```

The code produces the following output:

```text
Before first use: False
After first use: True
This XmlSerializerOptions instance is read-only.
After MakeReadOnly: True
```

## Best Practices

- **Create options once.** Keep each instance in a `static readonly` field or a singleton. Never create one per call: the type metadata is cached on the instance, and a new instance starts with none.
- **Set everything in the initializer.** An instance can't be changed after its first use, so finish configuring it where you create it.
- **Use the same instance to read and to write.** Naming policies, the default property mapping, and the default namespace change the names the serializer looks for when it reads.
- **Call `MakeReadOnly` before you share an instance** with code that might otherwise change it before its first use.
- **Copy at startup, not per call.** A copy shares none of the source's cached metadata.
- **Set `NewLine` when the output must be identical on every operating system.** Its default is `Environment.NewLine`, and it is used only when `WriteIndented` is `true`.
- **Start from `XmlSerializerOptions.Strict` for XML you don't control,** and set `MaxDocumentByteCount`. See [Security](/guides/security).

## Considerations

An options instance carries a cache as well as settings, which explains most of what follows.

### Read-only after first use

Serializing, deserializing, or calling `GetTypeInfo` or `TryGetTypeInfo` makes the instance read-only. From then on every setter throws an `InvalidOperationException` with the message `This XmlSerializerOptions instance is read-only.`, and so do changes to `Converters` and `TypeInfoResolverChain`. The three static instances are read-only from the start. To change a read-only instance, copy it with `new XmlSerializerOptions(existing)`.

### The cache lives on the instance

Each instance caches the converter and the type metadata for every type it has been used with. In the library's benchmark of a customer object with two addresses and 20 line items, a write with a new instance takes 612,933 ns and allocates 75,440 bytes, against 1,710 ns and no allocation with a cached instance. See [Benchmarks](/benchmarks). The cache is never trimmed, so an application that keeps creating instances also keeps their metadata alive for as long as it holds them.

### Zero means the built-in default

`IndentSize`, `DefaultBufferSize`, and the `Max*` limits are `0` on a new instance. For each of them, `0` selects the built-in value: an indent of 2, a 16,384-byte buffer, a depth of 64, 1,000 attributes, 1,024 bytes for a name, 16,777,216 bytes for a text value, and 1,048,576 bytes for a comment. `MaxDocumentByteCount` is the exception: `0` means no limit.

### Options that have no effect

The serializer doesn't read `AllowOutOfOrderMetadataProperties`, `InferClosedTypePolymorphism`, `PreferredObjectCreationHandling`, `RespectNullableAnnotations`, or `UnknownTypeHandling` in version 1.0. They can be set and copied, but they change nothing.

### Differences from JsonSerializerOptions

- `XmlSerializerDefaults.Web` sets only `PropertyNamingPolicy` to camelCase and `OmitXmlDeclaration` to `true`. It doesn't turn on case-insensitive matching.
- `RespectRequiredConstructorParameters` defaults to `true`.
- There are three naming policies for members instead of one: `PropertyNamingPolicy`, and `ElementNamingPolicy` and `AttributeNamingPolicy`, which override it for their kind of name.
- XML has options that JSON has no use for, such as `DefaultPropertyMapping`, `NilHandling`, `DefaultNamespace`, `OmitXmlDeclaration`, and `XmlVersion`.

### Thread safety

A read-only instance is meant to be shared between threads. See [Thread safety](/guides/thread-safety).
