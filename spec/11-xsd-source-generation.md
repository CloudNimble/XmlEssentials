# XSD source generation

Part of the [XmlEssentials spec](README.md).

XSD is a **compile-time** front-end to the [serializer generator](10-source-generation.md). It is not a runtime validator.

```text
*.xsd  →  POCOs + our attributes + [XmlSerializable]
       →  existing generator emits AOT Serialize/Deserialize
```

No `XmlSchemaSet`. No `XmlUrlResolver`. No schema documents on the Native AOT publish graph. The published binary knows types, not `.xsd` files.

## Input

MSBuild `AdditionalFiles` with `*.xsd` (and `*.wsdl` **ignored** — WSDL is out of scope). `xsd:include` / `xsd:import` resolve **only** to other AdditionalFiles in the same compilation, by file name or relative URI that maps to an AdditionalFile. Network, `file://` outside the compilation, and DTD inside a schema document are **errors** (XMLESS010).

```xml
<ItemGroup>
  <AdditionalFiles Include="Schemas\**\*.xsd" />
</ItemGroup>
```

Optional MSBuild metadata:

```xml
<AdditionalFiles Include="Schemas\order.xsd">
  <XmlEssentialsNamespace>MyApp.Xml.Order</XmlEssentialsNamespace>
  <XmlEssentialsContext>OrderXmlContext</XmlEssentialsContext>
</AdditionalFiles>
```

Defaults: C# namespace = root namespace + `.Generated`; context name = `{FileName}XmlContext`.

## Output (same compilation)

For each schema (and its includes/imports):

1. One `partial` class per named `xs:complexType`, named for the type, and one per global `xs:element` with an anonymous complex type, named for the element. A global element whose type is a named complex type gets no class of its own: its name is the `[XmlRoot]` name of the type's class (the first such element, with XMLESS018 when there are several).
2. Our mapping attributes: `[XmlRoot]`, `[XmlElement]`, `[XmlAttribute]`, `[XmlArray]` / `[XmlArrayItem]`, `[XmlText]`, nillable → nillable members.
3. `xs:extension` and `xs:restriction` of a named complex type → a derived class, and `[XmlPolymorphic(DiscriminatorPlacement = XsiType)]` + `[XmlDerivedType<T>("TypeName")]` on every class it derives from (not BCL `[XmlInclude]`). `xs:choice`, a group that repeats, and a `ref` to the head of a substitution group → one member that holds a per-member choice of elements (`[XmlElement<T>]` for each; K35), which needs the elements to be of different CLR types. See decisions 73 and 75 in [`24`](24-doc-findings-resolution.md).
4. `xs:simpleType` restrictions → the CLR type of the type they restrict, named or inline (enumerations → enum, with `[XmlPropertyName]` on a member whose value is not a C# identifier; patterns are **not** validated at runtime unless a converter is generated that enforces them — default: map to `string` and do not emit a regex validator; AOT must not pull `Regex` unless the consumer asked).
5. A `partial` `XmlSerializerContext` with `[XmlSerializable<T>]` for every generated root and reachable type.
6. XML doc comments from `xs:annotation` / `xs:documentation`.

Generated files use a stable header (`// <auto-generated />`) and are **not** user-edited. Users extend with another `partial` in their own files.

The serializer generator in the **same** analyzer DLL sees these types in the compilation (they are emitted before or in a second generator pass). Order: XSD generator runs as `IIncrementalGenerator` producing syntax; the context generator’s syntax provider includes generated `[XmlSerializable]` types. If two generators in one assembly need a sequence, use two `IIncrementalGenerator` classes in `CloudNimble.XmlEssentials.SourceGeneration` — XsdGenerator and SerializerGenerator. SerializerGenerator must accept types from the current compilation **including** generated ones (Roslyn does; generated syntax is in the compilation for subsequent generators in later pipelines — **do not** rely on same-pass visibility). Practical contract: XSD generator emits the POCOs + context **source**; the next compilation (or the serializer generator consuming `AdditionalTexts` + producing types that the serializer also walks via `ForAttributeWithMetadataName` after the first generator adds them) must work in `dotnet build`. If same-build visibility is insufficient, emit `[XmlSerializable]` as part of the XSD generator’s **own** serialization stubs is forbidden — keep one ser/deser emitter. Roslyn runs all incremental generators and then compiles combined output; **one build** is enough if SerializerGenerator uses `SyntaxProvider` on compilation after all generators… actually in Roslyn, generators cannot see each other’s output in the same compilation. **Contract:** the XSD generator emits POCOs **and** a partial context with `[XmlSerializable]`. It **also** invokes the same emit helpers the serializer generator uses for those types, **or** the consumer adds a **hand-written** partial context that lists `[XmlSerializable<Generated.Foo>]` in a second compilation.

**Chosen contract (AOT-safe, one `dotnet build`):** one analyzer DLL, two generator classes. The XSD generator emits:

- POCO syntax
- a `partial` context class with `[XmlSerializable<...>]` attributes
- **and** the `XmlTypeInfo` / serialize-deserialize implementation for those types, by calling shared emit APIs in the analyzer (not a second generator looking at the first’s output)

Hand-written contexts that reference generated types still go through SerializerGenerator as today. Generated contexts do not depend on SerializerGenerator seeing XSD output.

## AOT

| Rule | Why |
| --- | --- |
| No `.xsd` in the published app | Trimmer/ILC would have nothing useful to do with them; loading schema at runtime is reflection + URL resolve. |
| No `System.Xml.Schema` | Forbidden reference, same as other BCL XML. |
| Every generated type is in a context | Native AOT uses context overloads only. |
| Closed world | `xs:any` → `[XmlExtensionData]` / `XmlElementNode` list, not `object` + runtime type load. `xsi:type` values are the `[XmlDerivedType]` set from the schema, not `Type.GetType`. |
| No `XmlUrlResolver` / HTTP in the generator | Schemas must be AdditionalFiles. Build is offline. |
| `PublishAot=true` smoke test | Test asset includes a small `.xsd`, generates types, serializes via `Default` context. |
| Reflection disabled in that test | `IsReflectionEnabledByDefault=false`. |

## Mapping notes

| XSD | C# |
| --- | --- |
| `xs:string` etc. | CLR + [lexical rules](02-xml-fidelity.md) |
| `nillable="true"` | a member that can be null; a null is written as `xsi:nil` |
| `minOccurs="0"` | a member that can be null (`int?` for a value type); a null is left out |
| neither, on a reference type | a member that can be null because C# allows it; a null is left out with `[XmlIgnore(Condition = WhenWritingNull)]`, since only `nillable` permits `xsi:nil` |
| `maxOccurs` > 1 | `List<T>`, unwrapped |
| an element whose anonymous type is a sequence of one repeating element and nothing else | `List<T>` with `[XmlArray]` / `[XmlArrayItem]`: the outer element is the wrapper |
| `xs:attribute` | `[XmlAttribute]`; a value type is nullable unless `use="required"`; `use="prohibited"` gives no member; `ref="xml:lang"` keeps the XML namespace |
| `ref` on an element or attribute | the type of the global declaration |
| `xs:group ref`, `xs:attributeGroup ref` | the members of the named group, in place |
| a sequence nested in a sequence | its members, in place |
| `xs:anyAttribute` | `[XmlExtensionData]` attribute bag |
| `xs:any` | an `[XmlExtensionData]` member of type `XmlExtensionData` |
| `xs:extension` of a named complex type (complex or simple content) | CLR inheritance, with only the extension's own members on the derived class; **default** member order is base then derived. `[XmlPropertyOrder]` is **not** auto-emitted (schema sequence is per type, which matches default walk). |
| `abstract="true"` | an `abstract` class |
| anonymous complex type | nested class named `{Parent}_{Element}` |
| `xs:choice` of elements | one member `Item` with `[XmlElement<T>]` per alternative; its type is the nearest class all alternatives derive from, or `object`, or `XmlNamedValue` when two alternatives have one CLR type |
| a choice or sequence that repeats | one `List<T>` member `Items` with `[XmlElement<T>]` per element, including the elements of the groups nested in it, which keeps the order of the document; `List<XmlNamedValue>` when two elements have one CLR type. `Item` and `Items` are the generator's names: they take a number when the type, or a type it extends, uses the name |
| a choice or sequence that repeats around one element | a `List<T>` of that element, and the item of a wrapper when the group is all an anonymous type holds |
| `ref` to the head of a substitution group | one member with `[XmlElement<T>]` for the head (unless `abstract`) and each element that may stand for it, transitively; `XmlNamedValue` when two of them have one CLR type |
| `mixed="true"` | the attributes, and one `[XmlMixed] List<XmlMixedContentItem> Content`; the context lists `XmlMixedText` |
| `default` / `fixed` on an attribute, or on an element that must be present | a property initializer; a value type with a default is not nullable |
| element and attribute form | when every element is in the target namespace, members name none; otherwise each element member names its own (`""` for an unqualified local element, the target namespace for a global element or `form="qualified"`). A global attribute, a `ref` to one and `form="qualified"` / `attributeFormDefault="qualified"` put an attribute in the target namespace |

Not mapped, and reported: a choice that holds a sequence, a group or an element that repeats, which one value cannot hold (an optional member each, XMLESS011; no document is lost); a repeating group that holds `xs:any` or one element name with two types (a list each, which loses the order between them, XMLESS018); a `ref`, group or base type that is not in the schema (XMLESS018); `xs:restriction` of a named complex type, which is a derived class with no members (XMLESS011); `default` and `fixed` on an element that may be absent or of a type with no C# constant (XMLESS011). Members keep the order of the schema: the generator does not sort them with an unstable sort.
A type has no write fast path when it is abstract or has derived types, or a member holds one of those, a choice of elements, mixed content, extension data, or an element or item that names its own empty or other namespace through the form rules.
## Diagnostics

- XMLESS010: include/import not in AdditionalFiles, or DTD in a schema document
- XMLESS011 (info): the schema says something the generated code does not act on, and the documents stay the same (`xs:redefine`, `xs:notation`, identity constraints, `xs:choice`, `default`, `fixed`, a restriction of a complex type)
- XMLESS012: name collision in generated C#: two types in one namespace, two members of one class, a member named like its class, or two values of one enumeration
- XMLESS013: invalid XML name for a generated member
- XMLESS018 (warning): the schema allows a document the generated types cannot read or write as the schema describes it (a repeating group that holds a wildcard or one element name with two types, a missing `ref`, group or base type, several global elements of one type)

## Non-goals (this generator)

- Validating an instance document against the schema at runtime
- WSDL / SOAP bindings
- Emitting `System.Xml.Serialization` attributes
- Downloading schemas
