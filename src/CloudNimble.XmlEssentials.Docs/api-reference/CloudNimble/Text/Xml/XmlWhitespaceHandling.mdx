## Summary

How [Utf8XmlReader](/api-reference/CloudNimble/Text/Xml/Utf8XmlReader) treats whitespace-only text between elements.

## Usage

Set `XmlReaderOptions.WhitespaceHandling` to choose what a `Utf8XmlReader` does with text that is only white space and sits between elements. That's the indentation of a formatted document.

| Value | The reader |
| --- | --- |
| `Significant` | Reports the text as an `XmlTokenType.Text` token. This is the default. |
| `Insignificant` | Skips the text. |
| `None` | Throws an `XmlException` with the message `Whitespace-only text is not allowed.` |

With the default, the document below produces three `Text` tokens for the indentation inside `Order`. With `Insignificant`, they're gone:

```csharp
var xml = "<?xml-stylesheet href=\"order.xsl\"?>\n<Order>\n  <!-- rush -->\n  <Note><![CDATA[a < b]]></Note>\n</Order>"u8;

output.WriteLine("Default options:");
PrintTokens(xml, new XmlReaderOptions(), output);

var dataOnly = new XmlReaderOptions
{
    CommentHandling = XmlCommentHandling.Skip,
    WhitespaceHandling = XmlWhitespaceHandling.Insignificant,
};

output.WriteLine("Comments skipped and white space insignificant:");
PrintTokens(xml, dataOnly, output);
```

```text
Default options:
  ProcessingInstruction target=xml-stylesheet data="href="order.xsl""
  StartElement Order
  Text "\n  "
  Comment " rush "
  Text "\n  "
  StartElement Note
  CData "a < b"
  EndElement Note
  Text "\n"
  EndElement Order
Comments skipped and white space insignificant:
  ProcessingInstruction target=xml-stylesheet data="href="order.xsl""
  StartElement Order
  StartElement Note
  CData "a < b"
  EndElement Note
  EndElement Order
```

## Remarks

Whitespace inside a leaf element's value is always significant.
`<n> a </n>` is the value `" a "` regardless of this setting.

## Considerations

- **`Significant` is the zero value, and the default.** `new XmlReaderOptions()`, `default(XmlReaderOptions)`, and a reader created without options all report white space between elements. It's kept by default so that XML that's read and written back doesn't change its layout.
- **Set `Insignificant` in a loop that only wants data.** Otherwise the token after a start tag that has child elements is usually a `Text` token that holds indentation.
- **The serializer's default is different.** `XmlSerializerOptions.WhitespaceHandling` defaults to `Insignificant`, because indentation has no place in an object.
- **The setting never changes a value.** White space inside an element's text is part of the value under every setting: `<Name> Ada </Name>` is `" Ada "`. The reader doesn't trim. Line ends are read as a line feed under every setting, as XML requires.
- **White space outside the root element is never reported.** The line break after the XML declaration and anything after the root's end tag are skipped under every setting.
- **`None` rejects formatted documents.** Use it only when the producer is known to write no white space between elements and anything else is an error.
- **`XmlDocument` uses the same enumeration.** `XmlDocumentOptions.WhitespaceHandling` also defaults to `Significant`.

## Values

| Name | Value | Description |
|------|-------|-------------|
| `Insignificant` | 0 | Skip whitespace-only text between elements. This is the default. |
| `Significant` | 1 | Report whitespace-only text nodes as [XmlTokenType.Text](/api-reference/CloudNimble/Text/Xml/XmlTokenType). |
| `None` | 2 | Reject whitespace-only text between elements with [XmlException](/api-reference/CloudNimble/Text/Xml/XmlException). |
