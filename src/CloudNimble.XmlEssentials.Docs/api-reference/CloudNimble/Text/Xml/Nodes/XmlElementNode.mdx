## Summary

A mutable XML element with attributes and mixed children.

## Usage

`XmlElementNode` is an element in the mutable tree. It has a name (`LocalName`, `Prefix`, `NamespaceUri`), a list of `Attributes`, and a list of `Children` that can hold any kind of node.

The members you use most:

- `SetAttribute` adds an attribute or changes the value of one that exists.
- `AddElement` creates a child element, appends it, and returns it.
- `Add` appends any node.
- The indexer (`order["Item"]`) returns the first child element with a local name, or `null`.
- `InnerText` gets the text inside the element, or replaces the element's children with one text node.

```csharp
var order = new XmlElementNode("Order");
order.SetAttribute("id", "1042");

XmlElementNode customer = order.AddElement("Customer");
customer.Add(new XmlTextNode("Ada Lovelace"));

order.AddElement("Item").InnerText = "Keyboard";
order.AddElement("Item").InnerText = "Mouse & pad";
order.AddElement("Notes");

output.WriteLine(order.ToString());
```

The code produces the following output:

```xml
<Order id="1042"><Customer>Ada Lovelace</Customer><Item>Keyboard</Item><Item>Mouse &amp; pad</Item><Notes/></Order>
```

## Examples

### Add and insert children

```csharp
var order = (XmlElementNode)XmlNode.Parse("""<Order><Item>Keyboard</Item></Order>""")!;

order.AddElement("Item").InnerText = "Mouse";

var customer = new XmlElementNode("Customer");
customer.InnerText = "Ada Lovelace";
order.Children.Insert(0, customer);

order.Children.Insert(1, new XmlCommentNode(" items "));

output.WriteLine(order.ToString());
```

The code produces the following output:

```xml
<Order><Customer>Ada Lovelace</Customer><!-- items --><Item>Keyboard</Item><Item>Mouse</Item></Order>
```

### Set, change, and remove attributes

```csharp
var order = (XmlElementNode)XmlNode.Parse("""<Order id="1042" status="open" draft="true"/>""")!;

order.SetAttribute("status", "shipped");
order.SetAttribute("carrier", "Contoso Freight");
order.Attributes["id"]!.Value = "1043";

XmlAttributeNode draft = order.Attributes["draft"]!;
order.Attributes.Remove(draft);

output.WriteLine(order.ToString());
```

The code produces the following output:

```xml
<Order id="1043" status="shipped" carrier="Contoso Freight"/>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/30_ChangeWithXmlNode.cs)

### Put elements and attributes in namespaces

```csharp
const string atom = "http://www.w3.org/2005/Atom";
const string dc = "http://purl.org/dc/elements/1.1/";

var feed = new XmlElementNode("feed", atom);
feed.AddElement("title", atom).InnerText = "Release notes";

var creator = new XmlElementNode("creator", dc, "dc");
creator.InnerText = "Ada Lovelace";
feed.Add(creator);

XmlElementNode link = feed.AddElement("link", atom);
link.SetAttribute("href", "https://example.com/");
link.Attributes.Add(new XmlAttributeNode("language", "en", dc, "dc"));

output.WriteLine(feed.ToString());

feed.Attributes.Add(new XmlAttributeNode("dc", dc, XmlNamespaces.Xmlns, "xmlns"));
output.WriteLine(feed.ToString());

output.WriteLine($"{creator.Prefix}:{creator.LocalName} is in {creator.NamespaceUri}");
```

The code produces the following output:

```text
<feed xmlns="http://www.w3.org/2005/Atom"><title>Release notes</title><dc:creator xmlns:dc="http://purl.org/dc/elements/1.1/">Ada Lovelace</dc:creator><link href="https://example.com/" xmlns:dc="http://purl.org/dc/elements/1.1/" dc:language="en"/></feed>
<feed xmlns="http://www.w3.org/2005/Atom" xmlns:dc="http://purl.org/dc/elements/1.1/"><title>Release notes</title><dc:creator>Ada Lovelace</dc:creator><link href="https://example.com/" dc:language="en"/></feed>
dc:creator is in http://purl.org/dc/elements/1.1/
```

The writer declares each namespace where a name first needs it. Adding an `xmlns:dc` declaration attribute to the root, as the second half does, declares the prefix once.

## Best Practices

- **Use `SetAttribute` to add or change an attribute.** It never creates a duplicate.
- **Pass the namespace to `AddElement` for every element that belongs to one.** `feed.AddElement("title")` under a namespaced parent creates a `title` in no namespace, which is written with `xmlns=""`.
- **Set a prefix only when the spelling matters.** An element with a namespace and no prefix is written with a default namespace declaration. An attribute with a namespace and no prefix gets a generated prefix such as `ns1`.
- **Declare a shared prefix once on an ancestor.** Add an attribute with the prefix as its local name, `xmlns` as its prefix, and `XmlNamespaces.Xmlns` as its namespace.
- **Use the indexer for one child and a loop for many.** `order["Item"]` returns the first match only.
- **Read `InnerText` from the element that holds the value.** On an element with child elements it joins all the text below it, including the white space between the children in a tree parsed from an indented document.
- **Add your own white space when the layout matters.** A node you add to an indented tree isn't indented. Either add text nodes for the line break and indentation, or work on a tree without white space and write it with an indenting `Utf8XmlWriter`.

## Considerations

- `ValueKind` is always `Element`. The tree doesn't distinguish `<e/>` from `<e></e>`: an element with no children is written as an empty-element tag, and an element with children is written with an end tag.
- The one-argument indexer and `SetAttribute(name, value)` match a local name in any namespace. The overloads that take a namespace URI match that namespace only; pass an empty string for no namespace.
- The indexers return `null` when nothing matches. They search direct children only.
- `SetAttribute` stores a `null` value as an empty string. It doesn't remove the attribute.
- Setting `InnerText` removes every child, including child elements and comments, and adds one text node. Setting it to `null` or an empty string leaves the element empty.
- `LocalName` rejects `null`, an empty string, and white space when it's set. Whether the name is a valid XML name is checked only when the element is written.
- The element's namespace comes from its `NamespaceUri`. When the element is written, a namespace declaration attribute for the element's own prefix is written with the element's namespace, even if the attribute's value says something else.
- A prefix with no namespace can't be written; `ToString` and `WriteTo` throw an `XmlException` with the message "Prefixed names require a namespace URI.".
- `XmlElementNode` implements `IEnumerable<XmlNode>` over `Children`, so `foreach` and LINQ work on it directly. Changing `Children` while enumerating throws `InvalidOperationException`.
- An element allocates two lists when it's created, whether or not it ever has attributes or children.
