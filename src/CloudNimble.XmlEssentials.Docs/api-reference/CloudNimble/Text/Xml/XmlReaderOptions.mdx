## Summary

Options for [Utf8XmlReader](/api-reference/CloudNimble/Text/Xml/Utf8XmlReader).

## Usage

Create the options, set the properties you need, and pass the value to a `Utf8XmlReader` constructor. The reader copies the options, so later changes to your variable don't affect it.

The most common use is a reader that reports data only, without comments and without the white space between elements:

```csharp
var dataOnly = new XmlReaderOptions
{
    CommentHandling = XmlCommentHandling.Skip,
    WhitespaceHandling = XmlWhitespaceHandling.Insignificant,
};
```

```csharp
var reader = new Utf8XmlReader(utf8Xml, options);
```

The properties fall into three groups:

| Group | Properties |
| --- | --- |
| What the reader reports | `CommentHandling`, `WhitespaceHandling` |
| What counts as a document | `AllowMultipleRoots` |
| Limits | `MaxDepth`, `MaxAttributeCount`, `MaxNameByteCount`, `MaxTextByteCount`, `MaxCommentByteCount`, `MaxDocumentByteCount` |

When you read in blocks, the options travel in the [`XmlReaderState`](/api-reference/CloudNimble/Text/Xml/XmlReaderState): `new XmlReaderState(options)`.

## Remarks

A max-* of 0 means the default from the DoS table, except [XmlReaderOptions.MaxDocumentByteCount](/api-reference/CloudNimble/Text/Xml/XmlReaderOptions#maxdocumentbytecount)
which stays unbounded. Construct with `new XmlReaderOptions()` so
[XmlReaderOptions.CommentHandling](/api-reference/CloudNimble/Text/Xml/XmlReaderOptions#commenthandling) defaults to [XmlCommentHandling.Skip](/api-reference/CloudNimble/Text/Xml/XmlCommentHandling).

## Examples

Each example is a sample in the repository whose output is checked by a test.

### Set limits

Each call reads the same document with one limit lowered. The last call uses the defaults.

```csharp
var xml = "<Order note=\"gift\" rush=\"true\"><Customer><Name>Ada Lovelace</Name></Customer></Order>"u8;

output.WriteLine(Drain(xml, new XmlReaderOptions { MaxDepth = 2 }));
output.WriteLine(Drain(xml, new XmlReaderOptions { MaxAttributeCount = 1 }));
output.WriteLine(Drain(xml, new XmlReaderOptions { MaxNameByteCount = 4 }));
output.WriteLine(Drain(xml, new XmlReaderOptions { MaxTextByteCount = 8 }));
output.WriteLine(Drain(xml, new XmlReaderOptions { MaxDocumentByteCount = 64 }));
output.WriteLine(Drain(xml, new XmlReaderOptions()));
```

```text
XmlException: MaxAttributeCount exceeded (1).
XmlException: MaxNameByteCount exceeded (4).
XmlException: MaxTextByteCount exceeded (8).
XmlException: MaxDocumentByteCount exceeded (64).
Read 7 tokens.
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/21_ReadMarkupAndHandleErrors.cs)

### Read a fragment

```csharp
var options = new XmlReaderOptions { AllowMultipleRoots = true };
var reader = new Utf8XmlReader("<Item>Keyboard</Item><Item>Mouse</Item>"u8, options);
while (reader.Read())
{
    if (reader.TokenType is XmlTokenType.Text)
    {
        output.WriteLine(reader.GetString());
    }
}
```

```text
Keyboard
Mouse
```

## Best Practices

- **Set `CommentHandling` to `Skip` and `WhitespaceHandling` to `Insignificant` when your code only wants data.** The defaults report comments and the white space between elements, which is what code that copies or edits a document needs.
- **Leave the limits at their defaults unless you have a reason.** The defaults already protect against documents that nest too deep, carry too many attributes, or hold a name or a value that's too large.
- **Set `MaxDocumentByteCount` for input you don't trust.** It's the one limit that's off by default.
- **Lower `MaxDepth` when you know the shape of your documents.** A document format that nests five levels has no need for 64.
- **Use `XmlCommentHandling.Disallow` and `XmlWhitespaceHandling.None` only for a strict contract** between programs, where a comment or indentation means that the producer is wrong.

See [Security](/guides/security) for how the limits fit together.

## Considerations

Know the following about the defaults and the limits.

### The defaults keep everything

`new XmlReaderOptions()` and `default(XmlReaderOptions)` are the same value. `CommentHandling` is `Allow` and `WhitespaceHandling` is `Significant`, so the reader reports comments as `Comment` tokens and white-space-only text between elements as `Text` tokens. The XML specification asks a processor to pass all of a document's characters to the application, and XML that's read and written back then keeps its comments and layout. `XmlSerializerOptions` has the opposite defaults, because neither belongs in an object.

### A limit of 0 means the default

| Property | When it's 0 |
| --- | --- |
| `MaxDepth` | 64 |
| `MaxAttributeCount` | 1,000 |
| `MaxNameByteCount` | 1,024 bytes |
| `MaxTextByteCount` | 16,777,216 bytes |
| `MaxCommentByteCount` | 1,048,576 bytes |
| `MaxDocumentByteCount` | No limit |

`MaxDocumentByteCount` is the exception: 0 means no limit. The reader checks it in its constructor, against the bytes read in earlier blocks plus the length of the block it's given.

### What the limits count

- `MaxAttributeCount` includes namespace declarations.
- `MaxNameByteCount`, `MaxTextByteCount`, and `MaxCommentByteCount` are in UTF-8 bytes, not characters.
- `MaxCommentByteCount` applies to comments that are skipped as well as to comments that are reported.
- Exceeding a limit throws an `XmlException` whose message names the property and the limit, such as `MaxDepth exceeded (64).`

### Where else the options apply

These options are for `Utf8XmlReader`. `XmlDocument` and `XmlSerializer` have their own options types, `XmlDocumentOptions` and `XmlSerializerOptions`.
