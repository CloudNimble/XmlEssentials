## Summary

Options for [XmlDocument.Parse](/api-reference/CloudNimble/Text/Xml/XmlDocument#parse).

## Usage

Pass an `XmlDocumentOptions` to `XmlDocument.Parse` or `XmlDocument.TryParse` to choose what the parser keeps and what it rejects. `default`, `new XmlDocumentOptions()`, and a call to `Parse` without options all mean the same options.

The defaults are chosen so that there are no surprises on a round trip: a document that is parsed and written back with `XmlDocument.WriteTo` keeps its comments and the white space between its elements. When you only read values and don't want either in the document:

- Set `CommentHandling` to `XmlCommentHandling.Skip` to leave comments out. `Disallow` rejects a document that contains one.
- Set `WhitespaceHandling` to `XmlWhitespaceHandling.Insignificant` to leave out text that is only white space between elements. `None` rejects a document that contains it.

```csharp
const string xml = "<Order><!-- rush --><Item>Keyboard</Item></Order>";

using (XmlDocument kept = XmlDocument.Parse(xml))
{
    output.WriteLine($"Allow (the default): {CountChildren(kept.RootElement)} children");
    foreach (XmlElement child in kept.RootElement.EnumerateChildren())
    {
        output.WriteLine($"  {child.ValueKind}: '{child.GetString()}'");
    }
}

var skip = new XmlDocumentOptions { CommentHandling = XmlCommentHandling.Skip };
using (XmlDocument skipped = XmlDocument.Parse(xml, skip))
{
    output.WriteLine($"Skip: {CountChildren(skipped.RootElement)} child");
}

var disallow = new XmlDocumentOptions { CommentHandling = XmlCommentHandling.Disallow };
try
{
    using XmlDocument rejected = XmlDocument.Parse(xml, disallow);
}
catch (XmlException ex)
{
    output.WriteLine($"Disallow: {ex.Message}");
}
```

`CountChildren` is a helper in the sample that counts the nodes `EnumerateChildren` returns. The code produces the following output:

```text
Allow (the default): 2 children
  Comment: ' rush '
  Element: 'Keyboard'
Skip: 1 child
Disallow: Comments are not allowed.
```

The options are:

| Property | Controls | Default |
| --- | --- | --- |
| `CommentHandling` | Whether comments are kept, dropped, or rejected | `Allow` (kept) |
| `WhitespaceHandling` | What happens to white space that is the only text between two tags | `Significant` (kept) |
| `MaxDepth` | How deeply elements nest | 0, which means 64 |
| `MaxAttributeCount` | Attributes on one element, namespace declarations included | 0, which means 1,000 |
| `MaxNameByteCount` | One element or attribute name, in UTF-8 bytes | 0, which means 1,024 |
| `MaxTextByteCount` | One text node or CDATA section, in UTF-8 bytes | 0, which means 16,777,216 |
| `MaxCommentByteCount` | One comment, in UTF-8 bytes | 0, which means 1,048,576 |
| `MaxDocumentByteCount` | The whole document, in UTF-8 bytes | 0, which means no limit |

## Remarks

A max-* of 0 means the default from the DoS table, except [XmlDocumentOptions.MaxDocumentByteCount](/api-reference/CloudNimble/Text/Xml/XmlDocumentOptions#maxdocumentbytecount)
which stays unbounded. Construct with `new XmlDocumentOptions()` so
[XmlDocumentOptions.CommentHandling](/api-reference/CloudNimble/Text/Xml/XmlDocumentOptions#commenthandling) defaults to [XmlCommentHandling.Skip](/api-reference/CloudNimble/Text/Xml/XmlCommentHandling).

## Examples

### Limit untrusted input

A limit that is exceeded throws an `XmlException` whose message names the limit.

```csharp
var options = new XmlDocumentOptions
{
    MaxDepth = 2,
    MaxDocumentByteCount = 64,
};

try
{
    using XmlDocument tooDeep = XmlDocument.Parse("<a>**<c/>**</a>", options);
}
catch (XmlException ex)
{
    output.WriteLine(ex.Message);
}

try
{
    using XmlDocument tooLarge = XmlDocument.Parse($"<a>{new string('x', 100)}</a>", options);
}
catch (XmlException ex)
{
    output.WriteLine(ex.Message);
}
```

The code produces the following output:

```text
MaxDepth exceeded (2).
MaxDocumentByteCount exceeded (64).
```

### Leave out white space between elements

By default the indentation of a document is kept as `Text` nodes. `Insignificant` leaves it out.

```csharp
const string xml = """
    <Order>
      <Item>Keyboard</Item>
      <Item>Mouse</Item>
    </Order>
    """;

using (XmlDocument document = XmlDocument.Parse(xml))
{
    XmlElement order = document.RootElement;
    output.WriteLine($"Significant (the default): {CountChildren(order)} children");
    foreach (XmlElement child in order.EnumerateChildren())
    {
        output.WriteLine($"  {child.ValueKind}");
    }

    output.WriteLine($"  Text of the root: '{order.GetString()!.Replace("\n", "\\n")}'");
    output.WriteLine($"  Text of the first Item: '{order.GetChild("Item").GetString()}'");
}

var options = new XmlDocumentOptions { WhitespaceHandling = XmlWhitespaceHandling.Insignificant };
using (XmlDocument document = XmlDocument.Parse(xml, options))
{
    XmlElement order = document.RootElement;
    output.WriteLine($"Insignificant: {CountChildren(order)} children");
    output.WriteLine($"  Text of the root: '{order.GetString()}'");
}
```

The code produces the following output:

```text
Significant (the default): 5 children
  Text
  Element
  Text
  Element
  Text
  Text of the root: '\n  Keyboard\n  Mouse\n'
  Text of the first Item: 'Keyboard'
Insignificant: 2 children
  Text of the root: 'KeyboardMouse'
```

## Best Practices

- **Keep the defaults when the document is written back.** `CommentHandling.Allow` and `WhitespaceHandling.Significant` are what keep comments and indentation through a round trip.
- **Set `Skip` and `Insignificant` when you only read values.** The children of an element are then only the nodes that carry data, and the text of an element doesn't include indentation.
- **Set `MaxDocumentByteCount` for input you don't control.** It's the only limit with no default, and with the `Stream` overload of `Parse` it stops the read as soon as the stream is found to be longer.
- **Lower `MaxDepth` when you know the shape.** The default of 64 is generous for most formats.
- **Use `Disallow` or `None` to enforce a contract,** for example a message format that must not carry comments.

## Considerations

- `XmlDocumentOptions` is a struct. `default(XmlDocumentOptions)` and `new XmlDocumentOptions()` are the same options: `CommentHandling` is `Allow` and `WhitespaceHandling` is `Significant` in both.
- `XmlReaderOptions` has the same two defaults, so a `Utf8XmlReader` reports comments and white-space-only text as well. `XmlSerializer` skips both. A document keeps them so that `XmlDocument.WriteTo` reproduces the comments and the layout that were parsed.
- Because white space is kept, `XmlElement.EnumerateChildren` on an indented document returns a `Text` node for each run of indentation, and the text of an element that has child elements includes it. Lookups by name and the values of leaf elements aren't affected.
- `WhitespaceHandling` applies only to text that is nothing but white space between two tags. White space inside a value, such as `<Item> Keyboard </Item>`, is always kept.
- White space outside the root element isn't stored under any setting.
- A limit of 0 means the default limit in the table under Usage, except `MaxDocumentByteCount`, where 0 means no limit.
- `MaxDocumentByteCount` counts UTF-8 bytes. For the `string` and `ReadOnlySpan<char>` overloads of `Parse`, it applies to the size after conversion to UTF-8.
- `XmlDocument.ParseValue` doesn't take these options. The `XmlReaderOptions` of the reader you pass apply.
- `XmlNode.Parse` takes no options. It keeps comments and white space and uses the default limits. To build a mutable tree with other options, parse with `XmlDocument` and call `XmlElement.CloneNode`.
